## Question 1: What major features were introduced in Java 8?

**Priority:** 🔥 Must Know
**Source:** ➕ Interviewer expansion
**Difficulty:** Beginner
**Interview Frequency:** Very High

### Short Interview Answer

Java 8 introduced several major features that changed how Java code could be written, especially Lambda expressions, functional interfaces, the Stream API, method references, Optional, and default/static methods in interfaces. Lambdas and Streams particularly enabled a more declarative and functional style of programming.

For fresher interviews, prioritize:

- Lambda Expressions
- Functional Interfaces
- Stream API
- Method References
- Optional
- Default Methods

## Question 2: Why were Lambda expressions introduced?

**Priority:** 🔥🔥 Must Know | 🧠 Deep Understanding

### The Problem Before Lambda

Suppose we want to create a thread.

Before Lambda:

```java
Runnable task = new Runnable() {

    @Override
    public void run() {
        System.out.println("Task running");
    }
};

new Thread(task).start();
```

Look at how much code expresses one simple idea:

> "When run, print this."

The actual behavior is:

```java
System.out.println("Task running");
```

Everything else is ceremony.

### With Lambda

```java
Runnable task =
        () -> System.out.println("Task running");

new Thread(task).start();
```

Now the behavior becomes the focus.

### Root Motivation

Before:

```
Want to pass behavior
        ↓
create anonymous class
        ↓
implement method
        ↓
lots of boilerplate
```

After:

```
Want to pass behavior
        ↓
lambda expression
```

## Question 3: What is a Lambda expression?

**Priority:** 🔥🔥 Must Know

### Short Interview Answer

A Lambda expression is a concise way to provide an implementation for the single abstract method of a functional interface. It lets us represent behavior as a value that can be passed to methods, stored in variables, or used by APIs such as Streams.

Example:

```java
(a, b) -> a + b
```

Conceptually:

```
parameters
    ↓
(a, b)

arrow
    ↓
   ->

behavior
    ↓
a + b
```

### Lambda Forms

No parameter:

```java
() -> System.out.println("Hello");
```

One parameter:

```java
name -> System.out.println(name);
```

Multiple parameters:

```java
(a, b) -> a + b;
```

Multiple statements:

```java
(a, b) -> {
    int result = a + b;
    return result;
};
```

## Question 4: What is a functional interface?

**Priority:** 🔥🔥 Must Know

### Short Interview Answer

A functional interface is an interface with exactly one abstract method. Because there is one abstract behavior to implement, Java can use a Lambda expression as its implementation. The interface may still contain default and static methods.

Example:

```java
@FunctionalInterface
interface Calculator {

    int calculate(int a, int b);
}
```

Lambda:

```java
Calculator addition =
        (a, b) -> a + b;
```

Usage:

```java
System.out.println(
        addition.calculate(10, 20)
);
```

Output:

```
30
```

### Why Exactly One Abstract Method?

Suppose:

```java
interface Calculator {

    int add(int a, int b);

    int subtract(int a, int b);
}
```

and we write:

```java
(a, b) -> a + b
```

Java would ask:

```
Which method?

add()?
subtract()?
Ambiguous.
```

With one abstract method:

```
Lambda
   ↓
one clear target method
```

## Question 5: Is @FunctionalInterface mandatory?

**Priority:** 🔥 Important | ⚠️ Tricky

No.

This works:

```java
interface Printer {
    void print(String value);
}
```

because it already has one abstract method.

But:

```java
@FunctionalInterface
interface Printer {
    void print(String value);
}
```

is better when that is the design intention.

Why? Because the compiler protects the contract.

If someone later adds:

```java
void scan();
```

the compiler reports an error.

So:

```
@FunctionalInterface
→ optional annotation
→ useful compiler/design protection
```

## Question 7: What is Predicate\<T\>?

**Priority:** 🔥🔥 Must Know

A Predicate:

```
T → boolean
```

It takes something and answers:

```
true / false
```

Its main method is:

```java
boolean test(T t);
```

Example:

```java
Predicate<Integer> isEven =
        number -> number % 2 == 0;
```

Usage:

```java
System.out.println(isEven.test(10));
```

Output:

```
true
```

### Real Stream Usage

```java
numbers.stream()
       .filter(number -> number % 2 == 0);
```

The lambda used by `filter()` behaves as a Predicate.

Usage:

```java
Integer result =
        length.apply("Java");
```

Output:

```
4
```

Mental model:

```

   ↓
Function
   ↓
4
```

## The Four Functional Interfaces — Must Memorize the Shape

| Interface     | Input | Output  | Main method |
|---------------|-------|---------|-------------|
| `Predicate<T>`  | T     | boolean | `test()`    |
| `Function<T,R>` | T     | R       | `apply()`   |

| `Supplier<T>`   | none  | T       | `get()`     |

Best mental model:

```
Predicate → CHECK
Function  → TRANSFORM
Consumer  → CONSUME
Supplier  → SUPPLY
```

## Question 11: Lambda vs Anonymous Class

**Priority:** 🔥 Important | ⚠️ Tricky

Anonymous class:

```java
Runnable r = new Runnable() {

    @Override
    public void run() {
        System.out.println("Running");
    }
};
```

Lambda:

```java
Runnable r =
        () -> System.out.println("Running");
```

Both can provide behavior for this functional interface, but don't think:

> "A lambda is just syntactic sugar that always creates an anonymous class."

That's too simplistic.

The JVM has dedicated machinery for Lambda implementation and doesn't require Java to compile every lambda into an ordinary anonymous inner-class `.class` file.

For fresher interviews, the main difference to understand is:

```
Anonymous class
→ creates an anonymous class body

Lambda
→ concise implementation of functional behavior
```

## Question 12: Can Lambda access local variables?

**Priority:** 🔥 Important | ⚠️ Famous Question

Yes, but captured local variables must be:

```
final
```

or

```
effectively final
```

Example:

```java
int number = 10;

Runnable r =
        () -> System.out.println(number);
```

Valid because `number` is never reassigned. This is effectively final.

But:

```java
int number = 10;

number = 20;

Runnable r =
        () -> System.out.println(number);
```

is invalid.

### What Does "Effectively Final" Mean?

You didn't explicitly write:

```java
final int x = 10;
```

but after assignment:

```java
int x = 10;
```

you never change it.

Therefore the compiler treats it as effectively final for capture purposes.

## Question 13: What is a method reference?

**Priority:** 🔥 Must Know
**Source:** ➕ Added

### Short Interview Answer

A method reference is a concise syntax for referring to an existing method when a Lambda would simply call that method without adding extra behavior.

Lambda:

```java
name -> System.out.println(name)
```

Method reference:

```java
System.out::println
```

### Example

```java
List<String> names =
        List.of("A", "B", "C");

names.forEach(
        System.out::println
);
```

Instead of:

```java
names.forEach(
        name -> System.out.println(name)
);
```

### Common Method Reference Types

**Static method**

```java
ClassName::staticMethod
```

Example:

```java
Integer::parseInt
```

**Instance method of a particular object**

```java
object::method
```

Example:

```java
System.out::println
```

**Instance method of arbitrary object of a type**

```java
String::length
```

**Constructor reference**

```java
User::new
```

Example:

```java
Supplier<User> supplier =
        User::new;
```

## Question 14: Lambda vs Method Reference

**Priority:** ⭐ Important

Use Lambda when you're expressing logic:

```java
x -> x * x
```

Use method reference when the Lambda only delegates:

```java
System.out::println
```

instead of:

```java
x -> System.out.println(x)
```

Method references don't give new capabilities. They give cleaner syntax where an existing method already represents the behavior.

## Question 15: What is the Stream API?

**Priority:** 🔥🔥🔥 Must Know
**Source:** ➕ Interviewer expansion

### Short Interview Answer

The Stream API provides a declarative way to process sequences of elements through operations such as filtering, transformation, sorting, aggregation, and collection. A Stream doesn't normally store the data itself; it processes elements from a source such as a collection.

Example:

```java
List<Integer> numbers =
        List.of(1, 2, 3, 4, 5, 6);

List<Integer> evenNumbers =
        numbers.stream()
               .filter(n -> n % 2 == 0)
               .toList();
```

Result:

```
[2, 4, 6]
```

### Why Was Stream API Introduced?

Traditional:

```java
List<Integer> result =
        new ArrayList<>();

for (Integer number : numbers) {

    if (number % 2 == 0) {
        result.add(number);
    }
}
```

Stream:

```java
List<Integer> result =
        numbers.stream()
               .filter(n -> n % 2 == 0)
               .toList();
```

Traditional style often says:

```
HOW to iterate
HOW to check
HOW to add
```

Stream style focuses more on:

```
WHAT transformation pipeline do I want?

numbers
  ↓
filter even
  ↓
collect result
```

## Question 16: Collection vs Stream

**Priority:** 🔥🔥 Must Know | ⚠️ Tricky

| Collection                  | Stream                          |
|------------------------------|----------------------------------|
| Stores/manages elements       | Processes elements               |
| Can normally be traversed repeatedly | Stream pipeline is normally single-use |
| Data structure                | Processing abstraction           |
| Eager storage                 | Operations can be lazy           |
| `List`, `Set`, etc.           | `Stream<T>`                      |

### Important Interview Answer

A Collection is primarily concerned with storing and managing data, while a Stream represents a computation pipeline over data.

### Can We Reuse a Stream?

Normally no.

```java
Stream<String> stream =
        names.stream();

stream.forEach(System.out::println);

stream.forEach(System.out::println);
```

The second terminal use results in failure because the stream has already been consumed.

Think:

```
Collection
→ reusable storage

Stream
→ one processing pipeline
```

`filter()` answers:

```
Should this element remain?
```

It accepts:

```
Predicate<T>
```

```java
List<Integer> numbers =
        List.of(1, 2, 3, 4, 5);
```

```
[4, 5]
```

```
1 → false → removed
2 → false → removed
3 → false → removed

5 → true  → kept
```

## Question 18: What is map()?

**Priority:** 🔥🔥 Must Know

`map()` transforms:

```
one element
    ↓
another element
```

Example:

```java
List<String> names =
        List.of("java", "spring");

List<String> result =
        names.stream()
             .map(String::toUpperCase)
             .toList();
```

Result:

```
[JAVA, SPRING]
```

Conceptually:

```
java   → JAVA
spring → SPRING
```

`map()` uses Function-like transformation semantics.

### filter() vs map()

Very common interview question.

```
filter
→ decides whether element remains

map
→ transforms element
```

Example:

```java
numbers.stream()
       .filter(n -> n % 2 == 0)
       .map(n -> n * n);
```

Input:

```
1 2 3 4 5
```

After filter:

```
2 4
```

After map:

```
4 16
```

## Question 19: What is flatMap()?

**Priority:** 🔥🔥 Must Know | ⚠️ Frequently Confused

This is easier if you first see the problem.

Suppose:

```java
List<List<String>> skills =
        List.of(
            List.of("Java", "Spring"),
            List.of("SQL", "Redis")
        );
```

Structure:

```
[
   [Java, Spring],
   [SQL, Redis]
]
```

We want:

```
[Java, Spring, SQL, Redis]
```

### Using map()

```java
skills.stream()
      .map(List::stream);
```

produces conceptually:

```
Stream<Stream<String>>
```

Nested streams.

### Using flatMap()

```java
List<String> result =
        skills.stream()
              .flatMap(List::stream)
              .toList();
```

Result:

```
[Java, Spring, SQL, Redis]
```

Mental model:

```
map
────────────────────────
A → B

flatMap
────────────────────────
A → container/stream of B
     ↓
flatten
     ↓
B B B B
```

### Classic map() vs flatMap()

Suppose:

```java
class Employee {
    List<String> getSkills();
}
```

We have:

```java
List<Employee> employees;
```

Using:

```java
employees.stream()
         .map(Employee::getSkills)
```

gives:

```
Stream<List<String>>
```

Using:

```java
employees.stream()
         .flatMap(
             employee ->
                 employee.getSkills()
                         .stream()
         )
```

gives:

```
Stream<String>
```

That's the root difference.

## Question 20: What is reduce()?

**Priority:** 🔥🔥 Must Know

`reduce()` combines multiple elements into one result.

Example:

```java
List<Integer> numbers =
        List.of(1, 2, 3, 4, 5);

int sum =
        numbers.stream()
               .reduce(
                   0,
                   (a, b) -> a + b
               );
```

Result:

```
15
```

Mental flow:

```
0 + 1 = 1
1 + 2 = 3
3 + 3 = 6
6 + 4 = 10
10 + 5 = 15
```

So:

```
many elements
      ↓
reduce
      ↓
one value
```

### A Cleaner Sum

```java
int sum =
        numbers.stream()
               .reduce(
                   0,
                   Integer::sum
               );
```

## Question 22: Intermediate vs Terminal Stream Operations

**Priority:** 🔥🔥 Must Know

Stream operations broadly fall into:

- Intermediate
- Terminal

### Intermediate

Return another Stream. Examples:

- `filter()`
- `map()`
- `flatMap()`
- `distinct()`
- `sorted()`
- `limit()`

Example:

```java
stream.filter(...)
      .map(...)
      .sorted()
```

The pipeline hasn't produced its final result yet.

### Terminal

Triggers/produces completion of the pipeline. Examples:

- `forEach()`
- `collect()`
- `reduce()`
- `count()`
- `findFirst()`
- `anyMatch()`

Example:

```java
stream.filter(...)
      .count();
```

## Question 23: What is lazy evaluation in Streams?

**Priority:** 🔥🔥 Must Know | 🧠 Deep Understanding

Intermediate operations are lazy.

Consider:

```java
Stream<Integer> stream =
        numbers.stream()
               .filter(n -> {
                   System.out.println(
                       "Filtering " + n
                   );

                   return n % 2 == 0;
               });
```

At this point, you may see:

```
nothing processed yet
```

Why? There is no terminal operation.

Now:

```java
stream.count();
```

causes the pipeline to execute as needed.

Mental model:

```
stream()
   ↓
filter()
   ↓
map()
   ↓
no terminal operation
   ↓
pipeline definition only


terminal operation
   ↓
execution begins
```

### Why Is Laziness Useful?

It enables optimization.

Consider:

```java
numbers.stream()
       .filter(n -> n > 100)
       .findFirst();
```

Once Stream finds the first matching element, it may not need to process every remaining element.

That's called:

```
short-circuiting
```

## Question 24: Are Streams modifying the original Collection?

**Priority:** 🔥 Must Know

Usually, stream operations such as `filter()` and `map()` don't mutate the source collection.

Example:

```java
List<Integer> numbers =
        List.of(1, 2, 3, 4);

List<Integer> even =
        numbers.stream()
               .filter(n -> n % 2 == 0)
               .toList();
```

Now:

```
numbers = [1, 2, 3, 4]

even    = [2, 4]
```

The original list wasn't transformed into `[2,4]`.

## Question 26: What is Optional\<T\>?

**Priority:** 🔥🔥 Must Know
**Source:** ➕ Added. The PDF contains occurrences of the English word "optional," but not a dedicated Core Java `java.util.Optional<T>` interview treatment in the sections retrieved.

### Short Interview Answer

`Optional<T>` is a container that represents either the presence of a non-null value or the absence of a value. It was introduced to make absence explicit in APIs and encourage callers to handle that case instead of blindly dereferencing a potentially null reference.

Example:

```java
Optional<User> user;
```

Conceptually:

```
Optional<User>

Either:

[ User ]

or

[ empty ]
```

### Why Was Optional Introduced?

Traditional:

```java
User findUser(Long id) {

    if (...) {
        return user;
    }

    return null;
}
```

Caller:

```java
User user = findUser(10L);

System.out.println(
        user.getName()
);
```

If no user:

```
NullPointerException
```

With Optional:

```java
Optional<User> findUser(Long id) {
    ...
}
```

Caller can see directly:

```
This operation may have no result.
```

### Spring Data Example

You have probably seen:

```java
Optional<User> user =
        userRepository.findById(id);
```

Then:

```java
User result =
        user.orElseThrow(
            () ->
                new UserNotFoundException(
                    "User not found"
                )
        );
```

This connects directly to our Exception module.

```java
Optional<String> optional =
```

```java
Optional.of(null);
```

### Optional.ofNullable(value)

Allows null:

```java
Optional<String> optional =
        Optional.ofNullable(name);
```

If `name == null`:

```
Optional.empty()
```

### Optional.empty()

Explicit absence:

```java
Optional<String> optional =
        Optional.empty();
```

## Question 28: orElse() vs orElseGet()

**Priority:** 🔥🔥 Must Know | ⚠️ Very Good Interview Trap

Suppose:

```java
Optional<User> optional =
        findUser();
```

**orElse:**

```java
User user =
        optional.orElse(
            createDefaultUser()
        );
```

The argument `createDefaultUser()` is evaluated before `orElse()` receives it.

So it can run even if Optional already contains a User.

### orElseGet()

```java
User user =
        optional.orElseGet(
            () -> createDefaultUser()
        );
```

The Supplier is executed only if needed.

Mental model:

```
orElse(value)
→ value already evaluated


orElseGet(supplier)
→ supplier invoked only when empty
```

This matters if creating the fallback is:

- expensive
- database operation
- API operation
- object construction

## Question 31: Why were default methods introduced?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Question 7

This is directly covered by the PDF.

The PDF gives the classic problem:

> Imagine 100 classes implement an existing interface. If you add another abstract method, all implementations must change. A default implementation allows the interface to evolve while existing classes can inherit that behavior.

### Short Interview Answer

Default methods were primarily introduced to allow interfaces to evolve without breaking all existing implementations. A new method can be added with a default implementation, while implementing classes may either inherit it or override it.

Example:

```java
interface Vehicle {

    void start();

    default void stop() {
        System.out.println("Stopping");
    }
}
```

Existing classes implementing only `start()` can continue working.

## Question 32: What happens when two interfaces have the same default method?

**Priority:** 🔥 Must Know | ⚠️ Tricky
**Source:** 📘 PDF

The PDF explicitly discusses this conflict and requires the implementing class to resolve the common default method.

Example:

```java
interface A {

    default void show() {
        System.out.println("A");
    }
}
```

```java
interface B {

    default void show() {
        System.out.println("B");
    }
}
```

Then:

```java
class C implements A, B {

    @Override
    public void show() {
        A.super.show();
    }
}
```

The ambiguity must be resolved.

## Question 33: Why were static methods introduced in interfaces?

**Priority:** ⭐ Important
**Source:** 📘 PDF Question 8 + clarification

The PDF says Java 8 allows utility-like static methods to be defined directly in interfaces.

Example:

```java
interface Validator {

    static boolean valid(String input) {
        return input != null
                && !input.isBlank();
    }
}
```

Usage:

```java
Validator.valid(value);
```

### Important Correction

The PDF additionally claims that this is better because "using a class is more expensive" than using an interface.

Do not use that as your interview motivation.

A stronger explanation is:

> Static interface methods allow utility/helper behavior closely related to an interface's abstraction to live with that interface's API. The motivation is API organization and evolution, not a general rule that interface method calls are inherently cheaper than class calls.

## Common Fresher Mistakes

**❌ 1. "Lambda is an anonymous function unrelated to interfaces."**

In Java, a Lambda needs a compatible:

```
functional interface target type
```

**❌ 2. "Functional interface can contain only one method."**

Wrong. It can contain many: `default`, `static`, `private` methods. It must have exactly one relevant abstract method.

**❌ 3. "Predicate transforms the object."**

No.

```
Predicate
→ boolean decision

Function
→ transformation
```

**❌ 4. "Consumer returns a value."**

No.

```
Consumer<T>
T → void
```

**❌ 5. "Supplier takes an argument."**

No.

```
Supplier<T>
() → T
```

**❌ 6. "filter and map are the same."**

No.

```
filter
→ keep/remove

map
→ transform
```

**❌ 7. "map automatically flattens nested Lists."**

No. That's the purpose of `flatMap()`.

**❌ 8. "Streams store data."**

No. Collections primarily store data. Streams process data.

**❌ 9. "Intermediate Stream operations run immediately."**

Usually they're lazy. Execution is driven by a terminal operation.

**❌ 10. "A Stream can be reused multiple times."**

Normally a consumed Stream cannot be reused. Create a new Stream from the source.

**❌ 11. "Optional means null can never occur."**

Optional doesn't magically eliminate all null-related bugs. It provides an explicit representation for absence in APIs.

**❌ 12. "orElse() and orElseGet() are identical."**

Their fallback evaluation behavior differs.

## Interviewer Grill Round — Java 8+

**Interviewer:** What major change did Lambda expressions bring to Java?

**Candidate:** They allowed behavior for functional interfaces to be expressed concisely and passed around, reducing anonymous-class boilerplate and enabling APIs such as Streams.

---

**Interviewer:** What is a functional interface?

**Candidate:** An interface having exactly one abstract method, making it a valid target for a Lambda expression.

---

**Interviewer:** Can it have ten default methods?

**Candidate:** Yes. Default and static methods don't prevent it from being functional as long as it has one abstract method.

---

**Interviewer:** What is @FunctionalInterface?

**Candidate:** An optional annotation documenting the intention and allowing the compiler to enforce that functional-interface contract.

---

**Interviewer:** Predicate vs Function?

**Candidate:** Predicate takes a value and produces boolean; Function takes a value and transforms it into another value.

---

**Interviewer:** Consumer?

**Candidate:** Consumes a value and returns no result.

---

**Interviewer:** Supplier?

**Candidate:** Takes no input and supplies a value through `get()`.

---

**Interviewer:** Why must captured local variables be effectively final?

**Candidate:** Java Lambda capture works with values from the surrounding local scope, and allowing those local variables to be reassigned would create problematic semantics around the captured value. Java therefore requires captured local variables to be final or effectively final.

---

**Interviewer:** What is a method reference?

**Candidate:** A shorter syntax for using an existing method where a Lambda would simply delegate to that method, such as `System.out::println`.

---

**Interviewer:** What is a Stream?

**Candidate:** A processing pipeline over elements from a source. It doesn't normally store those elements itself; it lets us perform declarative operations such as filtering, mapping and reducing.

---

**Interviewer:** Collection vs Stream?

**Candidate:** A Collection primarily stores and manages elements. A Stream represents computation over elements and is generally consumed once.

---

**Interviewer:** What does filter() take?

**Candidate:** Predicate-style logic returning boolean to determine whether an element remains in the stream.

---

**Interviewer:** What does map() do?

**Candidate:** Transforms each input element into an output element using Function-like behavior.

---

**Interviewer:** Then explain flatMap() without using textbook language.

**Candidate:** If each original element produces multiple nested elements, `map()` leaves that nesting in place, while `flatMap()` both performs that transformation and flattens those nested streams into one stream.

---

**Interviewer:** Example?

**Candidate:** If each Employee contains `List<String> skills`, `map(Employee::getSkills)` gives a stream of Lists, whereas `flatMap(employee -> employee.getSkills().stream())` gives one stream of individual skills.

---

**Interviewer:** What is reduce()?

**Candidate:** An operation that repeatedly combines stream elements to produce one result, such as summing all integers.

---

**Interviewer:** Intermediate vs terminal operation?

**Candidate:** Intermediate operations such as `filter()` and `map()` return another Stream and are typically lazy. Terminal operations such as `collect()`, `count()` or `reduce()` trigger completion of the pipeline.

---

**Interviewer:** Why are Streams lazy?

**Candidate:** It allows operations to be combined and optimized, and short-circuit operations can avoid processing elements that aren't needed.

---

**Interviewer:** What is Optional?

**Candidate:** A container representing either a present non-null value or absence. It helps make the possibility of no result explicit.

---

**Interviewer:** Optional.of(null)?

**Candidate:** Throws NullPointerException.

---

**Interviewer:** Then what if value may be null?

**Candidate:** Use `Optional.ofNullable(value)`.

---

**Interviewer:** Difference between orElse() and orElseGet()?

**Candidate:** `orElse()` receives an already evaluated fallback argument, while `orElseGet()` receives a Supplier and evaluates it only when the Optional is empty.

---

**Interviewer:** Why were default interface methods introduced?

**Candidate:** Primarily to allow interfaces to evolve compatibly. A new method can have a default implementation so existing implementations don't all break immediately.

---
