## Question 1: What are Generics in Java?

**Priority:** 🔥 Must Know
**Source:** 📘 PDF Question 70

**Difficulty:** Beginner
**Interview Frequency:** Very High

### What the Interviewer Is Testing

Whether you understand why `<T>` exists rather than only being able to write syntax such as:

```java
List<String>
```

### Short Interview Answer

Generics allow classes, interfaces, and methods to work with types supplied as parameters. Their main benefit is compile-time type safety: instead of storing everything as `Object` and performing casts later, we can specify the expected type and let the compiler reject incompatible values. They also help us write reusable algorithms that work with different types.

The PDF emphasizes exactly these advantages: compile-time type safety, avoiding casts, and reusable type-safe algorithms.

## Question 2: Why were Generics introduced?

**Priority:** 🔥🔥 Must Know | 🧠 Deep Understanding
**Source:** 📘 PDF + interviewer expansion

This is the real foundation.

Before Generics, code often looked like:

```java
List list = new ArrayList();

list.add("Abhilash");
list.add(100);
list.add(true);
```

The collection accepts all of them.

Why?

Because conceptually it stores:

```
Object
```

The PDF uses essentially this exact before-generics example: a raw `List` accepts both a `String` and an `Integer`.

Now:

```java
String name = (String) list.get(0);
```

works.

But what if:

```java
String name = (String) list.get(1);
```

The actual object is:

```
Integer
```

so at runtime:

```
ClassCastException
```

### The Root Problem

Without Generics:

```
Compiler:

"I only know this List contains Objects."
                    ↓
                accepts values
                    ↓
Programmer performs casts
                    ↓
wrong assumption
                    ↓
runtime failure
```

Generics move the problem earlier:

```java
List<String> names = new ArrayList<>();

names.add("Abhilash");
names.add("Rahul");

// names.add(100);  // compile-time error
```

Now:

```
wrong type
   ↓
compiler rejects
   ↓
application never reaches runtime
```

This is much safer.

## Question 3: What is compile-time type safety?

**Priority:** 🔥 Must Know

### Short Interview Answer

Compile-time type safety means the compiler can verify that the types used with a generic class or collection match the declared type before the program runs. This prevents many type-related errors from becoming runtime failures.

Example:

```java
List<Integer> numbers =
        new ArrayList<>();

numbers.add(10);
numbers.add(20);
```

Invalid:

```java
numbers.add("Java");
```

Compiler says, conceptually:

```
Expected Integer
Received String
```

This is one of the primary advantages explicitly highlighted by the PDF.

### Why Is Compile-Time Failure Better?

Compare:

**Without Generics**

```
Code compiles
     ↓
Application deployed
     ↓
Production request occurs
     ↓
ClassCastException 💥
```

**With Generics**

```
Code written
     ↓
Compiler detects mismatch
     ↓
Developer fixes it immediately
```

That's an important engineering benefit.

**Priority:** 🔥 Must Know
**Source:** 📘 PDF

Before Generics:

```java
List list = new ArrayList();

list.add("Java");

String value =
        (String) list.get(0);
```

Because:

```java
list.get(0)
```

returns:

```
Object
```

Now with Generics:

```java
List<String> list =
        new ArrayList<>();

list.add("Java");

String value =
        list.get(0);
```

No explicit cast.

## Question 5: What is a generic class?

**Priority:** 🔥 Must Know | 💻 Coding
**Source:** 📘 PDF example + expansion

The PDF demonstrates a generic `Test<T>` class holding a `T obj`, then creates both `Test<String>` and `Test<Integer>`.

Let's build it from first principles.

Suppose we write:

```java
class Box {

    private String value;

    public void set(String value) {
        this.value = value;
    }

    public String get() {
        return value;
    }
}
```

This only works for:

```
String
```

What if tomorrow we need:

```
Integer
Employee
User
Order
```

We could write:

```
StringBox
IntegerBox
EmployeeBox
UserBox
```

That's duplicate code.

### Generic Version

```java
class Box<T> {

    private T value;

    public void set(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }
}
```

Now:

```java
Box<String> stringBox =
        new Box<>();

stringBox.set("Java");

String value =
        stringBox.get();
```

And:

```java
Box<Integer> integerBox =
        new Box<>();

integerBox.set(100);

Integer number =
        integerBox.get();
```

Same class.
Different type parameter.

### What Does T Mean?

```java
class Box<T>
```

`T` is a:

```
type parameter
```

When we write:

```java
Box<String>
```

`String` is the:

```
type argument
```

Think:

```
Definition:

Box<T>
    ↓
T = placeholder


Usage:

Box<String>
    ↓
T becomes String
```

### Common Type Parameter Names

You'll frequently see:

```
T → Type
E → Element
K → Key
V → Value
N → Number
R → Result/Return
```

Examples from the JDK:

```java
List<E>

Map<K, V>

Optional<T>
```

These are conventions, not special keywords.

This is legal:

```java
class Box<Anything> {
}
```

But:

```java
<T>
```

is the conventional style.

## Question 6: Can a generic class have multiple type parameters?

**Priority:** ⭐ Important

Yes.

Example:

```java
class Pair<K, V> {

    private K key;
    private V value;

    Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public V getValue() {
        return value;
    }
}
```

Usage:

```java
Pair<Integer, String> user =
        new Pair<>(101, "Abhilash");
```

Conceptually:

```
K → Integer
V → String
```

This should immediately remind you of:

```java
Map<K, V>
```

## Question 7: What is a generic method?

**Priority:** 🔥 Must Know | 💻 Coding
**Source:** ➕ Interviewer expansion

A class doesn't have to be generic for one method to be generic.

Example:

```java
class Printer {

    public static <T> void print(T value) {
        System.out.println(value);
    }
}
```

Usage:

```java
Printer.print("Java");
Printer.print(100);
Printer.print(10.5);
```

### Important Syntax

Notice:

```java
public static <T> void print(T value)
```

The `<T>` appears:

```
before the return type
```

Structure:

```
access modifier
      ↓
   public

type parameter
      ↓
      <T>

return type
      ↓
     void

method
      ↓
    print()
```

### Generic Return Type

```java
public static <T> T identity(T value) {
    return value;
}
```

Usage:

```java
String name =
        identity("Abhilash");

Integer number =
        identity(10);
```

## Question 8: Generic class vs generic method

**Priority:** ⭐ Important

**Generic Class**

```java
class Box<T> {

    private T value;
}
```

`T` belongs to the class.

Usage:

```java
Box<String>
```

**Generic Method**

```java
static <T> T get(T value) {
    return value;
}
```

The method introduces its own type parameter.

### Interview Difference

```
Generic Class
→ type parameter applies to object/class context


Generic Method
→ type parameter applies only to that method invocation
```

## Question 9: What is a generic interface?

**Priority:** ⭐ Important
**Source:** ➕ Interviewer expansion

Example:

```java
interface Repository<T, ID> {

    T save(T entity);

    T findById(ID id);
}
```

Implementation:

```java
class UserRepository
        implements Repository<User, Long> {

    @Override
    public User save(User user) {
        return user;
    }

    @Override
    public User findById(Long id) {
        return new User();
    }
}
```

This resembles patterns you see in backend frameworks.

For example, the conceptual idea behind:

```java
JpaRepository<User, Long>
```

is:

```
Entity type → User
ID type     → Long
```

This is a perfect real-world use of Generics.

## Question 10: What is a raw type?

**Priority:** 🔥 Important | ⚠️ Tricky
**Source:** ➕ Added

Suppose:

```java
List<String> names =
        new ArrayList<>();
```

That's parameterized.

But:

```java
List names =
        new ArrayList();
```

is a:

```
raw type
```

The generic type information has been omitted.

### Why Are Raw Types Dangerous?

```java
List list =
        new ArrayList();

list.add("Java");
list.add(100);
```

The compiler loses much of its ability to protect you.

Later:

```java
String value =
        (String) list.get(1);
```

→ `ClassCastException`.

So raw types take us backward toward the problem Generics were introduced to solve.

### Why Do Raw Types Exist?

Primarily for compatibility with older pre-generics Java code.

Generics were added later to Java, so existing code needed to continue compiling/interoperating.

For modern code:

```java
List<String>
```

is preferred over:

```java
List
```

## Question 11: What is a bounded type parameter?

**Priority:** 🔥 Important | 🧠 Deep Understanding
**Source:** ➕ Added

Suppose we write:

```java
class Calculator<T> {
}
```

`T` could be:

```
String
User
Employee
Integer
Anything
```

But suppose the algorithm only makes sense for numbers.

We can restrict it.

```java
class Calculator<T extends Number> {

    private T value;

    Calculator(T value) {
        this.value = value;
    }
}
```

Now valid:

```java
new Calculator<Integer>(10);
new Calculator<Double>(10.5);
```

Invalid:

```java
new Calculator<String>("Java");
```

### Meaning of `extends` Here

In Generics:

```java
<T extends Number>
```

means:

```
T must be Number or a subtype of Number.
```

It can be used even when the upper bound is an interface.

Example:

```java
<T extends Comparable<T>>
```

So don't interpret generic `extends` as "class inheritance only."

It means:

```
upper bound
```

### Multiple Bounds

You can write:

```java
<T extends Number & Comparable<T>>
```

Meaning:

```
T must satisfy Number
AND
Comparable<T>
```

An interview nuance:

If a class bound exists, it must come first.

Conceptually:

```java
<T extends SomeClass & Interface1 & Interface2>
```

## Question 12: What is a wildcard in Generics?

**Priority:** 🔥🔥 Must Know
**Source:** ➕ Added — not developed by the PDF's single Generics question

Wildcard:

```
?
```

means:

```
some unknown type
```

Example:

```java
List<?> list;
```

This means:

```
A List of some particular type, but I don't know what that type is here.
```

It could reference:

```
List<String>
List<Integer>
List<User>
```

Example:

```java
static void print(List<?> list) {

    for (Object value : list) {
        System.out.println(value);
    }
}
```

Now:

```java
print(List.of("A", "B"));

print(List.of(1, 2, 3));
```

both work.

## Question 13: Why can't I safely add values to `List<?>`?

**Priority:** 🔥🔥 | ⚠️ Tricky

Suppose:

```java
List<?> list;
```

What is the actual type?

Could be:

```
List<String>
```

or:

```
List<Integer>
```

or:

```
List<Employee>
```

Now consider:

```java
list.add("Java");
```

Is that safe?

No.

What if the actual list is:

```
List<Integer>
```

Similarly:

```java
list.add(10);
```

What if it's:

```
List<String>
```

The compiler doesn't know.

Therefore:

```
unknown type
    ↓
cannot safely add arbitrary typed objects
```

You can safely retrieve as:

```
Object
```

because whatever the actual element type is, it ultimately is an `Object` reference.

## Question 14: What does `? extends Number` mean?

**Priority:** 🔥🔥 Must Know | ⚠️ Famous Interview Question

```java
List<? extends Number>
```

means:

```
A List whose element type is some unknown specific subtype of Number.
```

Could be:

```
List<Integer>
List<Double>
List<Float>
```

Example:

```java
static double sum(
        List<? extends Number> numbers) {

    double total = 0;

    for (Number n : numbers) {
        total += n.doubleValue();
    }

    return total;
}
```

Now both work:

```java
List<Integer> ints =
        List.of(1, 2, 3);

List<Double> doubles =
        List.of(1.5, 2.5);
```

### Why Can We Read Number?

Suppose actual type is:

```
Integer
```

Every `Integer`:

```
IS-A Number
```

Suppose actual type is:

```
Double
```

Every `Double`:

```
IS-A Number
```

Therefore:

```java
Number n = numbers.get(0);
```

is safe.

### But Why Can't We Add Integer?

Consider:

```java
List<? extends Number> numbers;
```

Actual list might be:

```
List<Double>
```

Then:

```java
numbers.add(10);
```

would insert an `Integer` into:

```
List<Double>
```

which would violate type safety.

So:

```
? extends Number

GOOD for reading Number values
NOT safe for adding specific Number subtypes
```

## Question 15: What does `? super Integer` mean?

**Priority:** 🔥🔥 Must Know

```java
List<? super Integer>
```

means:

```
A List whose element type is Integer or some superclass of Integer.
```

Possible actual types include:

```
List<Integer>
List<Number>
List<Object>
```

Now:

```java
list.add(10);
```

is safe.

Why?

`10` is an `Integer`.

And an `Integer` can legally exist inside:

```
List<Integer>
List<Number>
List<Object>
```

Therefore:

```
? super Integer
       ↓
safe to add Integer
```

### What Can We Read?

Suppose:

```java
Object value = list.get(0);
```

This is safe.

But:

```java
Integer value = list.get(0);
```

is not generally safe.

Why?

If the actual structure is:

```
List<Object>
```

it could contain some other `Object` too.

So the only universally safe retrieval type is:

```
Object
```

## Question 16: What is PECS?

**Priority:** 🔥🔥 Must Know | 🧠 Deep Understanding

You may have heard:

> Producer Extends, Consumer Super.

Do not memorize it without understanding.

### Producer Extends

Suppose your method only reads numbers from a list.

The list is producing numbers for your method.

Use:

```java
List<? extends Number>
```

Example:

```java
double sum(
        List<? extends Number> numbers) {
    ...
}
```

Think:

```
Collection PRODUCES T for me
        ↓
    ? extends T
```

### Consumer Super

Suppose your method needs to put `Integer` values into a list.

The list consumes `Integer`s.

Use:

```java
List<? super Integer>
```

Example:

```java
static void addNumbers(
        List<? super Integer> list) {

    list.add(10);
    list.add(20);
}
```

Think:

```
Collection CONSUMES T from me
        ↓
      ? super T
```

### PECS Mental Model

```
Need to READ T?
     ↓
? extends T


Need to WRITE T?
     ↓
? super T
```

More precisely:

```
Producer → extends
Consumer → super
```

## Question 17: `List<Object>` vs `List<?>`

**Priority:** 🔥 Important | ⚠️ Tricky

These are not equivalent.

**`List<Object>`**

Means:

```
This is specifically a List<Object>
```

You can add:

```java
list.add("Java");
list.add(100);
list.add(new User());
```

because all are `Object`s.

**`List<?>`**

Means:

```
This is a List of some unknown specific type
```

It might actually be:

```
List<String>
```

So you cannot add arbitrary objects.

### Example

This method:

```java
void process(List<Object> list) {
}
```

cannot accept:

```
List<String>
```

But:

```java
void process(List<?> list) {
}
```

can.

This leads to one of the most important Generics questions.

## Question 18: If `Integer` extends `Number`, is `List<Integer>` a subtype of `List<Number>`?

**Priority:** 🔥🔥 Must Know | ⚠️ Classic Trap

No.

This is called:

```
generic invariance
```

Even though:

```
Integer IS-A Number
```

it does not follow that:

```
List<Integer> IS-A List<Number>
```

### Why?

Imagine it were allowed:

```java
List<Integer> integers =
        new ArrayList<>();

List<Number> numbers =
        integers;   // imagine this were legal
```

Now:

```java
numbers.add(3.14);
```

`3.14` is:

```
Double
```

Now our original:

```
List<Integer>
```

contains:

```
Double
```

Type safety is broken.

Therefore Java rejects that assignment.

### This Is Why Wildcards Exist

If we want:

```
List<Integer>
List<Double>
List<Long>
```

to all be acceptable as number producers, write:

```java
List<? extends Number>
```

not:

```java
List<Number>
```

## Question 19: What is type erasure?

**Priority:** 🔥🔥 Must Know | 🧠 Advanced Fresher
**Source:** ➕ Added

### Short Interview Answer

Java Generics are primarily implemented using type erasure. Generic type information is mainly used by the compiler for type checking, and much of that parameter information is erased or replaced by bounds in the generated bytecode. This allowed Generics to be introduced while maintaining significant compatibility with older Java code.

Example source:

```java
List<String> names =
        new ArrayList<>();
```

and:

```java
List<Integer> numbers =
        new ArrayList<>();
```

At runtime, there are not two completely different classes named something like:

```
ArrayListOfString
ArrayListOfInteger
```

They are both runtime instances of:

```
ArrayList
```

### Conceptual Erasure

Source:

```java
class Box<T> {

    T value;

    T get() {
        return value;
    }
}
```

Conceptually, when `T` has no explicit bound, erased representation behaves approximately like:

```java
class Box {

    Object value;

    Object get() {
        return value;
    }
}
```

The compiler inserts appropriate casts/checks where needed.

This is a conceptual teaching model, not literal source code generated exactly like that.

### Bounded Erasure

If:

```java
class Box<T extends Number> {
    T value;
}
```

the bound is relevant during erasure, so conceptually `T` is represented around:

```
Number
```

rather than unrestricted `Object`.

## Question 20: If Generics use type erasure, why don't I need casts?

**Priority:** 🧠 Deep Understanding

Because the compiler knows the generic type during compilation.

You write:

```java
List<String> names =
        new ArrayList<>();

String name =
        names.get(0);
```

The compiler verifies:

```
List contains String
```

and generates the necessary bytecode behavior.

So:

```
Developer
→ doesn't manually cast

Compiler
→ performs type checking and inserts required conversions
```

## Question 21: Can we use primitive types with Generics?

**Priority:** 🔥 Must Know | ⚠️ Common Trap

No.

Invalid:

```java
List<int> numbers;
```

Valid:

```java
List<Integer> numbers;
```

Generics work with reference types.

Java bridges primitive values through:

```
Autoboxing
```

Example:

```java
List<Integer> numbers =
        new ArrayList<>();

numbers.add(10);
```

Conceptually:

```java
numbers.add(
        Integer.valueOf(10)
);
```

## Question 22: Can we create `new T()`?

**Priority:** ⭐ Important | ⚠️ Tricky

Consider:

```java
class Box<T> {

    T create() {
        return new T(); // invalid
    }
}
```

Why?

Because due to Java's generic/runtime model, the JVM doesn't generally have enough reified type information here to know which concrete constructor:

```
T
```

represents.

Is `T`:

```
String?
User?
Employee?
Something without no-arg constructor?
```

So:

```java
new T()
```

is not allowed.

### How Can We Solve This?

One pattern is supplying construction behavior.

For example:

```java
class Factory<T> {

    private final Supplier<T> supplier;

    Factory(Supplier<T> supplier) {
        this.supplier = supplier;
    }

    T create() {
        return supplier.get();
    }
}
```

Usage:

```java
Factory<User> factory =
        new Factory<>(User::new);
```

We'll understand `Supplier` in the Java 8 module.

## Question 23: Can we create a generic array?

**Priority:** ⭐ Important | ⚠️ Tricky

This is invalid:

```java
T[] array = new T[10];
```

Likewise:

```java
List<String>[] lists =
        new List<String>[10];
```

is not allowed directly.

### Why?

Arrays and Generics have different runtime type models.

Arrays are:

```
reified
```

meaning they know/check their component type at runtime.

Generics primarily use:

```
type erasure
```

Combining unrestricted generic arrays with erased component information could break type safety.

### Arrays Show Their Type at Runtime

Example:

```java
Object[] array =
        new String[10];

array[0] = "Java";
```

valid.

But:

```java
array[1] = 100;
```

throws:

```
ArrayStoreException
```

because the runtime knows:

```
actual array type = String[]
```

Generic collections don't work that way.

## Question 24: Can static fields use a class's type parameter?

**Priority:** ⭐ Important | ⚠️ Tricky

Consider:

```java
class Box<T> {

    static T value; // invalid
}
```

Why?

`T` belongs to an instantiated generic type context such as:

```
Box<String>
Box<Integer>
```

But a static field belongs to the class itself and is shared.

If it were allowed:

```
Box<String>.value
```

and

```
Box<Integer>.value
```

would conceptually refer to the same static state.

What type should it be?

```
String?
Integer?
```

That is inconsistent.

### Can a Static Method Be Generic?

Yes.

Important distinction:

```java
class Box<T> {

    static <E> void print(E value) {
        System.out.println(value);
    }
}
```

Here `E` is the static method's own generic type parameter.

It does not use the class's `T`.

## Question 25: Can I use `instanceof List<String>`?

**Priority:** ⭐ Important | ⚠️ Type Erasure Trap

No:

```java
if (obj instanceof List<String>) {
}
```

because runtime generic argument information such as `String` isn't available in the required reified form.

But:

```java
if (obj instanceof List<?>) {
}
```

is valid.

This is another consequence of type erasure.

## Question 26: Can generic methods be overloaded only by generic type arguments?

**Priority:** ⚠️ Tricky

Suppose:

```java
void process(List<String> list) {
}
```

and:

```java
void process(List<Integer> list) {
}
```

This is not allowed as two overloads.

Why?

After type erasure, both have essentially the same erased signature:

```
process(List)
```

leading to a:

```
name clash
```

This is a strong interviewer follow-up on type erasure.

## Question 27: What is the difference between `<T extends Number>` and `<? extends Number>`?

**Priority:** 🔥 Important | ⚠️ Often Confused

They look similar but serve different purposes.

### Type Parameter

```java
<T extends Number>
```

defines a named type parameter.

Example:

```java
static <T extends Number>
T first(List<T> list) {

    return list.get(0);
}
```

We can refer to:

```
T
```

multiple times.

### Wildcard

```java
List<? extends Number>
```

means:

```
List of some unknown subtype of Number
```

There is no named type parameter for us to reuse directly.

### Mental Model

```
<T extends Number>
→ define/name a type


<? extends Number>
→ accept an unknown compatible type
```

## Question 28: Why would we use `List<? extends Number>` instead of `List<Number>`?

**Priority:** 🔥🔥 Must Know

Because:

```java
List<Number>
```

accepts specifically a:

```
List<Number>
```

It does not accept:

```
List<Integer>
```

because Generics are invariant.

But:

```java
List<? extends Number>
```

can reference:

```
List<Integer>
List<Double>
List<Long>
```

when the method only needs to consume/read those values as `Number`s.

## Common Fresher Mistakes

**❌ 1. "Generics provide type safety at runtime."**

The main benefit is:

```
compile-time
```

type checking.

The PDF specifically emphasizes compile-time type safety.

**❌ 2. "Generics allow primitive types."**

No:

```java
List<int> // invalid
```

Use:

```java
List<Integer>
```

**❌ 3. "`List<Integer>` is a subclass of `List<Number>`."**

No.

Generics are invariant.

**❌ 4. "`? extends Number` means I can add any Number."**

Exactly the opposite trap.

The actual list might be:

```
List<Double>
```

so inserting an `Integer` would be unsafe.

**❌ 5. "`? super Integer` means I can read Integer safely."**

Not generally.

Safe retrieval type is:

```
Object
```

because the actual list may be `List<Object>`.

**❌ 6. "`List<?>` and `List<Object>` are identical."**

No.

```
List<Object>
→ specifically Object list

List<?>
→ list of unknown specific type
```

**❌ 7. "Raw `List` and `List<Object>` are the same."**

No.

Raw type disables/weakens generic type checking for compatibility purposes.

`List<Object>` still participates fully in Generics.

**❌ 8. "Type erasure means Generics provide no safety."**

Wrong.

The compiler uses generic information before erasure to enforce type correctness.

**❌ 9. "`new T()` should work because `T` is a type."**

Not in Java's erased generic model.

**❌ 10. "Wildcards and type parameters are identical."**

No.

```
<T>
→ named type variable

<?>
→ unknown type
```

## Interviewer Grill Round — Generics

Now assume the interviewer starts easy and gradually pushes you deeper.

**Interviewer**
What are Generics?

**Candidate**
Generics allow classes, interfaces, and methods to work with types supplied as parameters. They mainly provide compile-time type safety, reduce explicit casts, and allow reusable type-safe code.

**Interviewer**
What problem existed before Generics?

**Candidate**
Collections were commonly used as raw types storing `Object`s. That allowed unrelated types to enter the same collection, required explicit casts when retrieving values, and could produce `ClassCastException` at runtime.

**Interviewer**
Show me.

**Candidate**
Without Generics:

```java
List list = new ArrayList();

list.add("Java");
list.add(100);

String value =
        (String) list.get(1);
```

That compiles with weak/raw typing but can fail at runtime.

With:

```java
List<String> list =
        new ArrayList<>();
```

the compiler rejects `list.add(100)`.

**Interviewer**
What does `T` mean?

**Candidate**
It's a type parameter—a placeholder for a type that will be supplied when the generic class or method is used.

**Interviewer**
What's the difference between type parameter and type argument?

**Candidate**
In:

```java
class Box<T>
```

`T` is the type parameter.

In:

```java
Box<String>
```

`String` is the type argument.

**Interviewer**
Can we have multiple type parameters?

**Candidate**
Yes, for example:

```java
class Pair<K, V> {
}
```

or `Map<K,V>`.

**Interviewer**
What is a raw type?

**Candidate**
Using a generic type without supplying its type arguments, such as `List` rather than `List<String>`. It mainly exists for backward compatibility and loses much of the compile-time type safety.

**Interviewer**
If `Integer` extends `Number`, can I do this?

```java
List<Number> numbers =
        new ArrayList<Integer>();
```

**Candidate**
No. Generic types in Java are invariant. `List<Integer>` is not a subtype of `List<Number>`.

**Interviewer**
Why?

**Candidate**
Because if it were allowed, I could insert a `Double` through the `List<Number>` reference, which would corrupt the original `List<Integer>`.

**Interviewer**
Then how do I accept both `List<Integer>` and `List<Double>`?

**Candidate**
If I'm mainly reading Numbers, I can use:

```java
List<? extends Number>
```

**Interviewer**
Can you add `10` to that list?

**Candidate**
Not safely, because the actual list might be `List<Double>`. The wildcard represents an unknown specific subtype of `Number`.

**Interviewer**
Then when would you use `? super Integer`?

**Candidate**
When I need a list that can consume `Integer` values. It can represent `List<Integer>`, `List<Number>`, or `List<Object>`, and adding an `Integer` is safe to each.

**Interviewer**
What's PECS?

**Candidate**
Producer Extends, Consumer Super. If a structure mainly produces `T` for me to read, I use `? extends T`. If it mainly consumes `T` values that I provide, I use `? super T`.

**Interviewer**
`List<?>` vs `List<Object>`?

**Candidate**
`List<Object>` is specifically a list whose element type is `Object` and allows adding arbitrary objects. `List<?>` means a list of an unknown specific element type, so I can read values as `Object` but can't safely add arbitrary typed values.

**Interviewer**
What is type erasure?

**Candidate**
Java uses generic type information mainly during compilation for checking, and much of the type-parameter information is erased or replaced by its bound in bytecode. That means `ArrayList<String>` and `ArrayList<Integer>` don't become two separate runtime `ArrayList` classes.

**Interviewer**
Then why doesn't this work?

```java
obj instanceof List<String>
```

**Candidate**
Because the `String` type argument isn't available in a sufficiently reified runtime form after type erasure. `obj instanceof List<?>` is valid instead.

**Interviewer**
Why can't I write:

```java
new T();
```

**Candidate**
Because the generic parameter isn't generally reified at runtime, so Java doesn't know which concrete class constructor should be invoked, nor whether that type even has the required constructor.

**Interviewer**
Can I write:

```java
static T value;
```

inside `class Box<T>`?

**Candidate**
No. Static state belongs to the class rather than one parameterized instance, while the class may be used as both `Box<String>` and `Box<Integer>`. There isn't one class-level `T` that works for both.

**Interviewer**
Can a static method itself be generic?

**Candidate**
Yes. It introduces its own type parameter:

```java
static <T> T identity(T value) {
    return value;
}
```

**Interviewer**
Can I overload these?

```java
void process(List<String> x)

void process(List<Integer> x)
```

**Candidate**
No. Because of type erasure their erased signatures collide as `process(List)`.

**Interviewer**
Give me a real Spring/backend example of Generics.

**Candidate**
Repository APIs are a good example. Something conceptually like:

```java
Repository<User, Long>
```

uses one generic type for the entity and another for its identifier, giving reusable repository behavior while maintaining compile-time type safety.
