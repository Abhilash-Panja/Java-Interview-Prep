# Java OOP — Inheritance Through Bookings

We will use a scheduled ride booking to understand how a specialized class can reuse a general class's behavior.

## 1. Start with the requirement

Our `Booking` class already stores booking information and supports operations such as starting and cancelling a ride.

Now we want to represent a **scheduled booking** that also records a requested pickup time.

| Feature | General booking | Scheduled booking |
|---|---|---|
| Booking ID | Yes | Yes |
| Passenger name | Yes | Yes |
| Ride type and status | Yes | Yes |
| Start and cancellation operations | Yes | Yes |
| Requested pickup time | Not modeled in the base class | Added by the specialized class |

A scheduled booking is still a booking. In this exercise, it follows the same start and cancellation rules and adds pickup-time information.

The pickup time is stored as a simple text label such as `"09:00"` so we can focus on the class relationship.

## 2. Why consider inheritance?

We could write an unrelated `ScheduledBooking` class and copy the booking fields and operations into it. Then a change to the common cancellation logic would need to be maintained in both places.

Inheritance can let the specialized class reuse the general booking implementation. It also creates a type relationship: a scheduled booking can be used through the general `Booking` type.

The relationship matters as much as reuse. A subclass should represent a specialized kind of its superclass and preserve the behavior callers can rely on.

Sharing a few similar fields, by itself, is not enough reason to use inheritance.

## 3. Introduce `extends`

We can declare the relationship like this:

```java
class ScheduledBooking extends Booking {
    // Additional scheduled-booking details.
}
```

This excerpt shows the declaration syntax; a usable subclass also needs a constructor matching our initialization requirements, as shown next.

| Term | Class in our example |
|---|---|
| Superclass, base class, or parent class | `Booking` |
| Subclass, derived class, or child class | `ScheduledBooking` |

A subclass inherits eligible members from its superclass and may declare additional members. Public operations such as `cancel()` can be used through the subclass. [Official Java guide to inheritance](https://dev.java/learn/oop/inheritance/).

## 4. Add the specialized information

Assuming the `Booking` class from our previous lesson, the subclass is:

```java
class ScheduledBooking extends Booking {
    private String pickupTime;

    public ScheduledBooking(
            int bookingId, String passengerName, String pickupTime) {
        super(bookingId, passengerName);
        this.pickupTime = pickupTime;
    }

    public void showPickupTime() {
        System.out.println("Scheduled pickup: " + pickupTime);
    }
}
```

`ScheduledBooking` declares its new field and an operation for displaying it. It does not redefine the common cancellation logic.

The `new` expression can supply all the starting details:

```java
ScheduledBooking booking =
    new ScheduledBooking(101, "Abhilash", "09:00");
```

## 5. Understand `super(...)`

The subclass constructor contains:

```java
super(bookingId, passengerName);
```

This invokes the matching constructor of the direct superclass, `Booking`.

| Constructor call | Which constructor it invokes |
|---|---|
| `this(...)` | Another constructor of the same class |
| `super(...)` | A constructor of the direct superclass |

For this example:

1. Creation begins using the `ScheduledBooking` constructor.
2. `super(bookingId, passengerName)` invokes the two-argument `Booking` constructor.
3. That constructor uses our earlier `this(...)` chain to the three-argument `Booking` constructor, supplying `"STANDARD"`.
4. The `Booking` constructor initializes the common booking fields.
5. Execution returns to the subclass constructor, which stores `pickupTime`.

There is **one** `ScheduledBooking` object, containing the instance state defined by its superclass as well as its own field. Calling `super(...)` does not create a separate booking object inside it.

Constructors are not inherited. The subclass declares its own constructor and invokes a superclass constructor to initialize the superclass-defined state. [Official Java explanation of constructors and inheritance](https://dev.java/learn/oop/inheritance/).

## 6. Run the complete example

Save this as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        ScheduledBooking booking =
            new ScheduledBooking(101, "Abhilash", "09:00");

        booking.showDetails();
        booking.showPickupTime();

        booking.cancel();
        System.out.println("After cancellation: " + booking.getStatus());

        try {
            booking.startRide();
        } catch (IllegalStateException exception) {
            System.out.println("Rejected: " + exception.getMessage());
        }
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String rideType;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this(bookingId, passengerName, "STANDARD");
    }

    public Booking(int bookingId, String passengerName, String rideType) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = rideType;
        this.status = "CONFIRMED";
    }

    public void startRide() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException(
                "Only confirmed bookings can start."
            );
        }

        status = "STARTED";
    }

    public void cancel() {
        ensureCancellationAllowed();
        status = "CANCELLED";
    }

    private void ensureCancellationAllowed() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException(
                "Only confirmed bookings can be cancelled."
            );
        }
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(
            bookingId + " | " + passengerName + " | "
            + rideType + " | " + status
        );
    }
}

class ScheduledBooking extends Booking {
    private String pickupTime;

    public ScheduledBooking(
            int bookingId, String passengerName, String pickupTime) {
        super(bookingId, passengerName);
        this.pickupTime = pickupTime;
    }

    public void showPickupTime() {
        System.out.println("Scheduled pickup: " + pickupTime);
    }
}
```

With a JDK installed, run:

```bash
javac Main.java
java Main
```

Output:

```
101 | Abhilash | STANDARD | CONFIRMED
Scheduled pickup: 09:00
After cancellation: CANCELLED
Rejected: Only confirmed bookings can start.
```

The scheduled booking uses the inherited cancellation operation. Trying to start it afterward is rejected by the inherited start operation, following the same booking rules.

## 7. Identify where each operation comes from

| Call | Where the implementation is declared |
|---|---|
| `booking.showDetails()` | `Booking` |
| `booking.cancel()` | `Booking` |
| `booking.startRide()` | `Booking` |
| `booking.getStatus()` | `Booking` |
| `booking.showPickupTime()` | `ScheduledBooking` |

The class definition gives the object access to inherited public methods without requiring us to copy their source into `ScheduledBooking`.

## 8. What happens to the private fields?

Private superclass members are **not** inherited by the subclass. Our separate `ScheduledBooking` class cannot directly access `Booking`'s private `status` field or private validation helper. [Official Java rules for private superclass members](https://dev.java/learn/oop/inheritance/).

However, the object still contains the superclass-defined state. The inherited `cancel()` implementation is code declared in `Booking`, so it can access `Booking`'s own private field and helper.

This preserves the boundary from the encapsulation lesson. The subclass can use public methods such as `getStatus()` when it needs the exposed information.

Do not redeclare another `status` field in `ScheduledBooking` to work around access restrictions. That would create a separate field, while the inherited booking methods would still operate on the field declared in `Booking`.

## 9. Why the type relationship matters

A `Booking` variable can refer to a `ScheduledBooking` object:

```java
Booking booking = new ScheduledBooking(102, "Ravi", "10:30");
booking.cancel();
```

Code that works with the general booking operations can therefore work with the specialized booking too. It does not need a separate cancellation implementation for each kind of booking.

We will explore reference types and method selection further when we study polymorphism.

## 10. Use inheritance deliberately

Our example models `ScheduledBooking` as a specialized booking that obeys the existing booking contract.

In a real design, if the only difference is optional pickup-time information, adding that information to `Booking` may be enough. Inheritance becomes a design choice, not a requirement imposed by having one extra field.

If a specialized type changes the rules so it cannot satisfy the promises of the base type, reconsider the relationship or the contract. Reuse alone should not force an unsuitable hierarchy.

Java permits a class to have one direct superclass. In this example, `ScheduledBooking` directly extends `Booking`; `Booking` implicitly extends `Object`. That is an inheritance chain, not two direct superclasses. [Official Java description of single inheritance](https://dev.java/learn/oop/inheritance/).

## 11. Explain it in an interview

> Inheritance lets a class derive from another class, inherit eligible members, and add or specialize behavior. For example, a `ScheduledBooking` can extend `Booking`, reuse its public cancellation behavior, and add a requested pickup time. This represents an is-a relationship, so the specialized type should preserve the base type's contract. Constructors are not inherited, and private superclass members cannot be accessed directly by this subclass.

## 12. Check your understanding

Using the complete example, consider:

```java
ScheduledBooking booking =
    new ScheduledBooking(201, "Anita", "11:00");

booking.cancel();
```

`ScheduledBooking` does not declare `cancel()`. Where does its implementation come from, and which object's status does it change?
