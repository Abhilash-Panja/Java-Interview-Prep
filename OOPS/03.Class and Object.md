# Java OOP — Classes and Objects Through Bookings

We'll use ride bookings throughout this lesson.

---

## 1. Start With the Situation

You and Ravi each book a ride. Both bookings start out **confirmed**.

You cancel your booking. Ravi's booking must stay confirmed.

| Booking accessed through | Before your cancellation | After your cancellation |
|---|---|---|
| `abhilashBooking` | `CONFIRMED` | `CANCELLED` |
| `raviBooking` | `CONFIRMED` | `CONFIRMED` |

Both bookings follow the **same design**, but each needs to remember its **own** status.

**Goal:** define the booking structure and operations *once*, then create individual bookings from that definition.

---

## 2. The Class Defines What a Booking Has and Does

For this lesson we model two statuses: `CONFIRMED` and `CANCELLED`. Every new booking starts as confirmed.

```java
class Booking {
    private String status = "CONFIRMED";

    public void cancel() {
        status = "CANCELLED";
    }

    public String getStatus() {
        return status;
    }
}
```

**Read the class as:** *"Each booking has a status. It supports an operation to cancel it and an operation to read its current status."*

| Code | Meaning |
|---|---|
| `class Booking` | Defines the booking type |
| `status` | A field that stores each booking's current status |
| `cancel()` | A method that changes the receiving booking's status |
| `getStatus()` | A method that returns the receiving booking's status |

- `private` prevents ordinary code outside this class from directly accessing the field.
- The `public` methods provide the operations callers can use.
- `void` means a method returns no value; `String` on `getStatus()` means it returns text.

> **Class vs. Object:** A **class** defines a type and its structure and behavior. An **object** is an individual instance of that class. ([Official Java introduction to objects and classes](https://dev.java/learn/oop/))

Writing the class definition does **not**, by itself, create our two booking objects — that's the next step.

---

## 3. Create the Two Objects

Inside `main()`:

```java
Booking abhilashBooking = new Booking();
Booking raviBooking = new Booking();
```

Each `new Booking()` creates and initializes a **separate** booking object.

The class is defined once, but these statements create **two instances**. Each instance has its own `status` field, initially containing `"CONFIRMED"`.

### Breaking down the first statement

| Part | Meaning |
|---|---|
| `Booking` | The declared type of the variable |
| `abhilashBooking` | A reference variable through which this code accesses one object |
| `new Booking()` | Creates and initializes a booking object |
| `=` | Stores the resulting reference in the variable |

A **reference variable** is how this code accesses the object; the variable and the object are distinct concepts. Read the statement as:

> *"Create one booking object and access it through `abhilashBooking`."*

([Official Java guide to creating objects](https://dev.java/learn/classes-objects/creating-objects/))

The variable names simply help us tell the two bookings apart in this demo. This small class only stores `status` for now — no passenger name or booking ID yet.

---

## 4. Cancel One Booking

```java
abhilashBooking.cancel();
```

This means: *execute `cancel()` on the object accessed through `abhilashBooking`.*

Inside the method, this line runs:

```java
status = "CANCELLED";
```

It updates **that particular object's** status only — it does **not** update the separate object accessed through `raviBooking`.

The method implementation is written **once** in `Booking`. Each call uses the state of the object receiving the call. We don't need separate methods named `cancelAbhilashBooking()` and `cancelRaviBooking()`.

---

## 5. Run the Complete Example

Save as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        Booking abhilashBooking = new Booking();
        Booking raviBooking = new Booking();

        abhilashBooking.cancel();

        System.out.println("Abhilash: " + abhilashBooking.getStatus());
        System.out.println("Ravi: " + raviBooking.getStatus());
    }
}

class Booking {
    private String status = "CONFIRMED";

    public void cancel() {
        status = "CANCELLED";
    }

    public String getStatus() {
        return status;
    }
}
```

Run it:

```bash
javac Main.java
java Main
```

**Output:**

```
Abhilash: CANCELLED
Ravi: CONFIRMED
```

- `main()` starts this example.
- `System.out.println(...)` displays the results in the console.
- The code defines **one** `Booking` class and creates **two** `Booking` objects.
- `Main` is a separate class used to run the demonstration.

---

## 6. Connect the Terms

| Term | Booking example |
|---|---|
| **Class** | `Booking` — the shared definition |
| **Object** | One individual booking created by `new Booking()` |
| **Reference variable** | `abhilashBooking` or `raviBooking` |
| **Field** | `status` |
| **Method** | `cancel()` or `getStatus()` |
| **State** | A particular booking's current status |

`status` here is an **instance field** — each booking has its own copy. (Class-level `static` fields are a separate topic for later.)

---

## 7. Explain It in an Interview

> A class defines a type and the fields and methods its instances have. An object is an individual instance with its own instance state. For example, a `Booking` class can define `status` and cancellation behavior. Two booking objects can hold different statuses, so cancelling one booking does not cancel the other.

---

## 8. Check Your Understanding

Using the same `Booking` class, put this in a fresh `main()`:

```java
Booking first = new Booking();
Booking second = new Booking();

second.cancel();

System.out.println(first.getStatus());
System.out.println(second.getStatus());
```

**Predict:**
1. What are the two printed statuses?
2. Which object actually receives the cancellation request?

<details>
<summary>Click to reveal the answer</summary>

```
CONFIRMED
CANCELLED
```

`second.cancel()` only runs on the object referenced by `second`. `first` is a completely separate `Booking` object with its own `status` field, so it's untouched and remains `CONFIRMED`.
</details>
