# Java OOP — Constructors Through Bookings

A constructor initializes an object when it is created. We will use it to give each booking its own ID and passenger name.

## 1. Start with the problem

In the previous lesson, each booking remembered only its status. Now we want these two bookings:

| Booking | Booking ID | Passenger name | Initial status |
|---|---|---|---|
| Your booking | 101 | Abhilash | CONFIRMED |
| Ravi's booking | 102 | Ravi | CONFIRMED |

Both use the same `Booking` class, but they need different starting details.

Suppose we declare the fields without assigning values:

```java
class Booking {
    private int bookingId;
    private String passengerName;
}
```

Creating an instance of this class with `new Booking()` leaves `bookingId` at `0` and `passengerName` at `null`. These are Java's default values for those instance fields. `null` means the field does not refer to a `String` object.

Java cannot infer that this particular booking belongs to Abhilash and should have ID 101. Our code needs to supply that information.

We could create an object and then call separate methods to fill in its details. A caller could forget one of those steps. A constructor gives us a place to accept and assign the starting details as part of creating the object.

## 2. Add a constructor

```java
class Booking {
    private int bookingId;
    private String passengerName;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.status = "CONFIRMED";
    }
}
```

The constructor is this part:

```java
public Booking(int bookingId, String passengerName) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.status = "CONFIRMED";
}
```

Read it as:

> When this constructor is used to create a booking, accept its ID and passenger name, store them in the new object, and initialize its status as confirmed.

The constructor has the same name as the class and no return type, including no `void`. The `new` expression creates the instance and invokes its constructor to initialize it. [Official Java guide to creating and initializing objects](https://dev.java/learn/classes-objects/creating-objects/).

For this example, starting as `CONFIRMED` is our chosen rule. Java does not assign that business status automatically.

## 3. Supply the values during creation

Inside `main()`, write:

```java
Booking abhilashBooking = new Booking(101, "Abhilash");
Booking raviBooking = new Booking(102, "Ravi");
```

For the first statement:

- `new Booking(101, "Abhilash")` creates a new booking and invokes the constructor with those arguments.
- The constructor receives `101` in its `bookingId` parameter and `"Abhilash"` in its `passengerName` parameter.
- Its assignments store those values in this object's fields and set its status to `"CONFIRMED"`.
- After initialization succeeds, the expression produces a reference, which is stored in `abhilashBooking`.

The second statement creates a separate object and performs the same initialization using `102` and `"Ravi"`.

## 4. Understand `this` in the assignments

Look at:

```java
this.bookingId = bookingId;
```

Two things have the name `bookingId`:

| Expression | Meaning in this constructor |
|---|---|
| `this.bookingId` | The field belonging to the object being initialized |
| `bookingId` | The parameter holding the value passed by the caller |

When creating your booking, read the assignment as:

> Store the incoming value 101 in this booking object's `bookingId` field.

`this` refers to the current object. It lets us distinguish the field from a parameter with the same name. [Official Java explanation of this](https://dev.java/learn/classes-objects/more-on-classes/).

If we wrote only `bookingId = bookingId`, both names would refer to the parameter. That would not initialize the object's field.

## 5. Run the complete example

Save this as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        Booking abhilashBooking = new Booking(101, "Abhilash");
        Booking raviBooking = new Booking(102, "Ravi");

        abhilashBooking.showDetails();
        raviBooking.showDetails();

        abhilashBooking.cancel();

        System.out.println("After cancellation:");
        abhilashBooking.showDetails();
        raviBooking.showDetails();
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.status = "CONFIRMED";
    }

    public void cancel() {
        status = "CANCELLED";
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(
            bookingId + " | " + passengerName + " | " + status
        );
    }
}
```

With a JDK installed, run:

```bash
javac Main.java
java Main
```

Output:

```
101 | Abhilash | CONFIRMED
102 | Ravi | CONFIRMED
After cancellation:
101 | Abhilash | CANCELLED
102 | Ravi | CONFIRMED
```

`showDetails()` is an ordinary method that prints the object's current fields so we can see the result. The constructor sets the initial state; `cancel()` changes the state later.

## 6. Why did `new Booking()` work in the previous lesson?

That earlier class declared no constructors, so Java supplied a default constructor with no parameters. It also ran the instance field initialization we wrote for `status`.

Once we explicitly declare a constructor, Java does not supply that default constructor.

Our new class declares a constructor taking an `int` and a `String`, so these calls have different outcomes:

```java
new Booking(101, "Abhilash"); // Works: matches our constructor

new Booking(); // Compilation error: no matching no-argument constructor
```

We could explicitly add a no-argument constructor if the design needed one. Constructor overloading is a topic we can study next.

## 7. Distinguish construction from later operations

| Operation | Purpose in this example |
|---|---|
| `new Booking(101, "Abhilash")` | Create and initialize a booking |
| `abhilashBooking.cancel()` | Change the existing booking's status |
| `abhilashBooking.showDetails()` | Display the existing booking's current information |

The `new` expression produces the reference to the object; the constructor itself has no return type.

This constructor requires two arguments and assigns them. It does not validate whether an ID is positive, whether a name is empty, or whether an ID is unique. Such rules must be implemented deliberately when the application needs them.

## 8. Explain it in an interview

> A constructor initializes a new object. It has the same name as its class and no return type. For example, a Booking constructor can accept a booking ID and passenger name, assign them to the object's fields, and set an initial status. This lets different objects begin with different information while using the same class.

# Java OOP — Constructor Overloading Through Bookings

Constructor overloading means defining more than one constructor in the same class, with different parameter lists. It gives callers different ways to initialize objects of that class.

## 1. Start with a booking requirement

In the last lesson, we created a booking using an ID and passenger name:

```java
Booking booking = new Booking(101, "Abhilash");
```

Now imagine that our demo application offers two ride types: `STANDARD` and `PREMIUM`.

We choose this rule for the demo:

- If the caller does not specify a ride type, use `STANDARD`.
- If the caller supplies a ride type, store the supplied value.

The booking ID and passenger name are still required in both cases.

| Situation | Information supplied | Initial ride type |
|---|---|---|
| Use the default ride type | Booking ID and passenger name | STANDARD |
| Choose a ride type explicitly | Booking ID, passenger name, and ride type | The supplied value, such as PREMIUM |

This resembles a booking form where the standard option is selected initially, but the passenger can choose a premium ride. The Java example models the resulting initialization choices.

## 2. Give the class two constructors

One constructor accepts two arguments:

```java
public Booking(int bookingId, String passengerName) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.rideType = "STANDARD";
    this.status = "CONFIRMED";
}
```

The other constructor accepts three:

```java
public Booking(int bookingId, String passengerName, String rideType) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.rideType = rideType;
    this.status = "CONFIRMED";
}
```

These constructor excerpts belong inside the same `Booking` class. Both have the class name and no return type. Their parameter lists differ, so Java can distinguish them.

The two-argument constructor chooses the default ride type. The three-argument constructor uses the ride type received from the caller.

Java allows multiple constructors with different signatures; the arguments in an object-creation expression determine which applicable constructor is selected. [Official Java guide to object initialization](https://dev.java/learn/classes-objects/creating-objects/).

## 3. See how the calls match

### Two arguments

```java
Booking abhilashBooking = new Booking(101, "Abhilash");
```

This call supplies an `int` and a `String`. It matches our constructor with the parameter list `(int, String)`.

The constructor assigns the fields as follows:

```
bookingId = 101
passengerName = Abhilash
rideType = STANDARD
status = CONFIRMED
```

### Three arguments

```java
Booking raviBooking = new Booking(102, "Ravi", "PREMIUM");
```

This call supplies an `int`, a `String`, and another `String`. It matches our constructor with the parameter list `(int, String, String)`.

It produces:

```
bookingId = 102
passengerName = Ravi
rideType = PREMIUM
status = CONFIRMED
```

Both objects have the type `Booking`. Their starting field values differ.

## 4. Run the complete example

Save this as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        Booking abhilashBooking = new Booking(101, "Abhilash");
        Booking raviBooking = new Booking(102, "Ravi", "PREMIUM");

        abhilashBooking.showDetails();
        raviBooking.showDetails();
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String rideType;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = "STANDARD";
        this.status = "CONFIRMED";
    }

    public Booking(int bookingId, String passengerName, String rideType) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = rideType;
        this.status = "CONFIRMED";
    }

    public void cancel() {
        status = "CANCELLED";
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(
            bookingId + " | " + passengerName + " | "
            + rideType + " | " + status
        );
    }
}
```

With a JDK installed, run:

```bash
javac Main.java
java Main
```

Output:

```
101 | Abhilash | STANDARD | CONFIRMED
102 | Ravi | PREMIUM | CONFIRMED
```

Each `new Booking(...)` expression creates one booking object. Having two constructor definitions does not cause a single `new` expression to create two bookings.

## 5. Why this is useful

The common case can use the shorter call and the class's default ride type. A caller that needs a specific ride type can supply it during creation.

Both forms initialize the same fields, so later operations such as `cancel()` and `showDetails()` work with either object.

Constructor overloading gives us different creation options while keeping those objects under one class definition.

## 6. What makes constructor parameter lists different?

Constructor signatures can differ in the number or types of parameters, including their type order.

In our example, the difference is the number of parameters:

| Constructor parameter types | Number of parameters |
|---|---|
| `(int, String)` | 2 |
| `(int, String, String)` | 3 |

Parameter names alone do not distinguish constructors. For example, these two declaration headers have the same parameter types and would conflict if declared together:

```java
// Declaration headers for comparison; these are not complete constructors.
Booking(int bookingId, String passengerName)
Booking(int id, String name)
```

Both have the type sequence `(int, String)`. Renaming a parameter does not create a new overload.

For the simple calls in this lesson, the compiler can select the matching constructor from the supplied argument count and types. The passenger's actual name is not used to choose the overload.

## 7. The default is part of our code

Java does not automatically choose `STANDARD`. This assignment in our two-argument constructor supplies that default:

```java
this.rideType = "STANDARD";
```

The three-argument constructor simply stores its input. The example uses strings to keep the focus on constructors; this implementation does not restrict the argument to the two advertised ride types. Such validation would need to be added deliberately.

## 8. Explain it in an interview

> Constructor overloading means defining multiple constructors in the same class with different parameter lists. It provides different ways to initialize objects. For example, a Booking constructor can accept an ID and passenger name and choose a standard ride by default. Another constructor can also accept an explicit ride type. Both create instances of the same class.

# Java OOP — Constructor Chaining Through Bookings

We will improve the overloaded constructors from the previous lesson using `this(...)`. The examples use Java 17-compatible syntax.

## 1. Start with the repeated work

Our `Booking` class has two creation options:

```java
new Booking(101, "Abhilash");
new Booking(102, "Ravi", "PREMIUM");
```

The first uses a standard ride by default. The second accepts a ride type from the caller.

In the previous implementation, both constructors separately assigned the booking ID, passenger name, and initial status:

```java
// Excerpts from inside the previous Booking class:
public Booking(int bookingId, String passengerName) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.rideType = "STANDARD";
    this.status = "CONFIRMED";
}

public Booking(int bookingId, String passengerName, String rideType) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.rideType = rideType;
    this.status = "CONFIRMED";
}
```

Suppose the business later changes the initial status to `PENDING`. We would have to update both constructor implementations. If we forgot one, the starting status would depend on which constructor the caller used.

The problem is duplicated initialization logic that can drift apart.

## 2. Reuse the constructor that accepts all the details

The three-argument constructor already knows how to assign every field.

The two-argument constructor only needs to supply the missing ride type, `"STANDARD"`, and pass all three values to it:

```java
public Booking(int bookingId, String passengerName) {
    this(bookingId, passengerName, "STANDARD");
}

public Booking(int bookingId, String passengerName, String rideType) {
    this.bookingId = bookingId;
    this.passengerName = passengerName;
    this.rideType = rideType;
    this.status = "CONFIRMED";
}
```

From inside a constructor, `this(...)` invokes another constructor in the same class. This is one form of constructor chaining. [Official Java explanation of constructor invocation with this](https://dev.java/learn/classes-objects/creating-objects/).

Read the shorter constructor as:

> Use the supplied ID and passenger name, choose STANDARD as the ride type, and let the other constructor perform the initialization.

Now both creation options pass through the same field-assignment code.

## 3. A booking-office analogy

Imagine a booking office with two request forms:

- A short form containing the booking ID and passenger name.
- A detailed form that also contains a selected ride type.

The short form fills in `STANDARD` for the missing ride type. Both forms then use the same booking-registration procedure.

In our Java example, the shorter constructor supplies the default, and the longer constructor performs the shared initialization.

The analogy describes reuse of one procedure. In Java, both constructor bodies work on the same booking object being initialized.

## 4. Follow one creation step by step

Consider:

```java
Booking booking = new Booking(101, "Abhilash");
```

| Step | What happens |
|---|---|
| 1 | Creation of one `Booking` instance begins using the two-argument constructor. |
| 2 | Its `this(bookingId, passengerName, "STANDARD")` call invokes the three-argument constructor. |
| 3 | That constructor assigns this object's fields using `101`, `"Abhilash"`, and `"STANDARD"`. |
| 4 | After that constructor completes normally, execution resumes after `this(...)` in the two-argument constructor. |
| 5 | After construction completes normally, the resulting reference is assigned to `booking`. |

Both `Booking` constructors participate in this creation, but there is one booking object.

For `new Booking(102, "Ravi", "PREMIUM")`, the selected constructor is already the three-argument one. It performs the field assignments directly; the two-argument constructor is not called.

## 5. Run a complete example that prints the order

The constructor print statements below let us observe when shared initialization finishes and when the shorter constructor resumes.

Save the following as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Creating standard booking:");
        Booking abhilashBooking = new Booking(101, "Abhilash");
        abhilashBooking.showDetails();

        System.out.println("Creating premium booking:");
        Booking raviBooking = new Booking(102, "Ravi", "PREMIUM");
        raviBooking.showDetails();
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String rideType;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this(bookingId, passengerName, "STANDARD");
        System.out.println("Two-argument constructor: resumed");
    }

    public Booking(int bookingId, String passengerName, String rideType) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = rideType;
        this.status = "CONFIRMED";

        System.out.println("Three-argument constructor: fields initialized");
    }

    public void cancel() {
        status = "CANCELLED";
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(
            bookingId + " | " + passengerName + " | "
            + rideType + " | " + status
        );
    }
}
```

With a JDK installed, run:

```bash
javac Main.java
java Main
```

Output:

```
Creating standard booking:
Three-argument constructor: fields initialized
Two-argument constructor: resumed
101 | Abhilash | STANDARD | CONFIRMED
Creating premium booking:
Three-argument constructor: fields initialized
102 | Ravi | PREMIUM | CONFIRMED
```

For the standard booking, the first constructor message comes from the three-argument constructor. The two-argument constructor was selected first, but it immediately delegated before reaching its own print statement.

For the premium booking, there is no message from the two-argument constructor because that creation uses the three-argument constructor directly.

## 6. Distinguish three similar-looking expressions

| Expression | Meaning |
|---|---|
| `this.bookingId` | Access the current object's `bookingId` field |
| `this(bookingId, passengerName, "STANDARD")` | Invoke another constructor in the same class for the object being initialized |
| `new Booking(bookingId, passengerName, "STANDARD")` | Create a separate `Booking` object |

Replacing `this(...)` with `new Booking(...)` inside the shorter constructor would create an extra booking. It would not perform those field assignments on the original object.

## 7. Rules to remember

- Use `this(...)` inside a constructor to invoke a matching constructor of the same class.
- With Java 17, an explicit `this(...)` constructor invocation must be the first statement in the constructor body. Code can follow it.
- Constructor chaining must not form a cycle. Direct or indirect recursive constructor invocation is a compilation error.

These placement and recursion rules are specified in the Java 17 language specification for constructor bodies.

**Version note:** Java 25 introduced more flexible constructor bodies, allowing some statements before a constructor invocation under restrictions. The first-statement form used here also works with those newer rules. [Official Java guide to constructor bodies](https://dev.java/learn/classes-objects/creating-objects/).

An example of forbidden direct recursion is:

```java
// Invalid constructor excerpt: it invokes itself with the same signature.
public Booking(int bookingId, String passengerName) {
    this(bookingId, passengerName);
}
```

Our working version avoids that cycle: the two-argument constructor invokes the three-argument constructor, which does not invoke the two-argument one.

## 8. Overloading and chaining solve different needs

| Concept | Purpose in our example |
|---|---|
| Constructor overloading | Offer creation with either two or three arguments |
| Constructor chaining | Reuse the shared field initialization between those constructors |

Overloaded constructors do not have to invoke each other. Chaining is useful when their initialization work can be shared.

For example, if we later add a shared check for booking IDs, placing it in the three-argument constructor ensures that both of our current creation options go through that check.

## 9. Explain it in an interview

> Constructor chaining means one constructor invokes another as part of initializing an object. In the same class, we use `this(...)`. It helps share initialization logic. For example, a two-argument Booking constructor can supply a standard ride type and delegate to a three-argument constructor that assigns all the fields. Both constructor bodies work on the same booking instance.
