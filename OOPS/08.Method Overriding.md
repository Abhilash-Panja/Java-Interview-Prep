# Java OOP — Method Overriding Through Bookings

We will give `ScheduledBooking` its own version of `showDetails()` while reusing the common details printed by `Booking`.

## 1. Start with the missing information

In our inheritance example, `ScheduledBooking` inherited this method from `Booking`:

```java
public void showDetails() {
    System.out.println(
        bookingId + " | " + passengerName + " | "
        + rideType + " | " + status
    );
}
```

It prints the common booking fields. It does not know about the pickup-time field declared in `ScheduledBooking`.

To print both kinds of information, the caller previously used two operations:

```java
scheduledBooking.showDetails();
scheduledBooking.showPickupTime();
```

Now we want this single operation to display the details appropriate to the booking:

```java
booking.showDetails();
```

| Actual object | Desired details |
|---|---|
| `Booking` | ID, passenger, ride type, and status |
| `ScheduledBooking` | The common fields plus requested pickup time |

The operation has the same purpose for both types: display that booking's details. The specialized type needs an implementation that includes its additional information.

## 2. Give the subclass its own implementation

Add this method inside `ScheduledBooking`:

```java
@Override
public void showDetails() {
    super.showDetails();
    showPickupTime();
}
```

The superclass already declares the instance method `public void showDetails()`. The subclass now declares a method with the matching signature and a compatible return type.

This is **method overriding**: a subclass provides an implementation of an inherited instance method. [Official Java guide to method overriding](https://dev.java/learn/oop/inheritance/).

An ordinary `Booking` object continues to use `Booking.showDetails()`. A `ScheduledBooking` object uses its override when that instance method is invoked normally.

## 3. Understand the two calls inside the override

```java
super.showDetails();
```

This explicitly invokes the superclass implementation of `showDetails()` for the same object. It prints the common booking fields.

Then:

```java
showPickupTime();
```

This calls the method already declared in `ScheduledBooking`, which prints the pickup-time field.

The override extends the displayed information without copying the common printing logic.

## 4. What does `@Override` do?

`@Override` asks the compiler to check that this declaration really overrides or implements an appropriate inherited method.

For example, if we accidentally wrote `showDetail()` instead of `showDetails()`, the annotation would help the compiler report that the declaration does not match the intended inherited method.

The annotation does not create overriding behavior. A correctly matching method still overrides without it. Using the annotation helps catch mistakes. [Official Java explanation of @Override](https://dev.java/learn/oop/inheritance/).

## 5. See the complete subclass

Assuming our existing `Booking` class:

```java
class ScheduledBooking extends Booking {
    private String pickupTime;

    public ScheduledBooking(
            int bookingId, String passengerName, String pickupTime) {
        super(bookingId, passengerName);
        this.pickupTime = pickupTime;
    }

    public void showPickupTime() {
        System.out.println("Scheduled pickup: " + pickupTime);
    }

    @Override
    public void showDetails() {
        super.showDetails();
        showPickupTime();
    }
}
```

The inherited booking operations still manage the common state. The new override specializes the display operation.

## 6. Run the complete example

Save the following as `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        Booking regularBooking = new Booking(101, "Abhilash");
        Booking scheduledBooking =
            new ScheduledBooking(102, "Ravi", "09:00");

        System.out.println("Regular booking:");
        regularBooking.showDetails();

        System.out.println("Scheduled booking:");
        scheduledBooking.showDetails();
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String rideType;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this(bookingId, passengerName, "STANDARD");
    }

    public Booking(int bookingId, String passengerName, String rideType) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = rideType;
        this.status = "CONFIRMED";
    }

    public void startRide() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException(
                "Only confirmed bookings can start."
            );
        }

        status = "STARTED";
    }

    public void cancel() {
        ensureCancellationAllowed();
        status = "CANCELLED";
    }

    private void ensureCancellationAllowed() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException(
                "Only confirmed bookings can be cancelled."
            );
        }
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(
            bookingId + " | " + passengerName + " | "
            + rideType + " | " + status
        );
    }
}

class ScheduledBooking extends Booking {
    private String pickupTime;

    public ScheduledBooking(
            int bookingId, String passengerName, String pickupTime) {
        super(bookingId, passengerName);
        this.pickupTime = pickupTime;
    }

    public void showPickupTime() {
        System.out.println("Scheduled pickup: " + pickupTime);
    }

    @Override
    public void showDetails() {
        super.showDetails();
        showPickupTime();
    }
}
```

With a JDK installed, run:

```bash
javac Main.java
java Main
```

Output:

```
Regular booking:
101 | Abhilash | STANDARD | CONFIRMED
Scheduled booking:
102 | Ravi | STANDARD | CONFIRMED
Scheduled pickup: 09:00
```

The same public operation displays common details for one object and additional scheduled-booking information for the other.

## 7. Why does the override run through a `Booking` reference?

Look at:

```java
Booking scheduledBooking =
    new ScheduledBooking(102, "Ravi", "09:00");

scheduledBooking.showDetails();
```

| Part | Type |
|---|---|
| Declared reference type | `Booking` |
| Actual object type | `ScheduledBooking` |

The compiler allows the call because `Booking` declares `showDetails()`. At runtime, normal instance-method dispatch selects the override for the actual `ScheduledBooking` object.

Inside that override, the explicit `super.showDetails()` call selects the superclass implementation for the common printing step.

This behavior is the basis of **runtime polymorphism**, which we will explore in the next lesson.

## 8. Compare constructor calls with superclass method calls

| Expression | Meaning |
|---|---|
| `super(bookingId, passengerName)` | Invoke a superclass constructor during initialization |
| `super.showDetails()` | Invoke the superclass implementation of a method |
| `this(...)` | Invoke another constructor in the same class |

`super.showDetails()` is a method call, so it is not subject to the constructor-invocation placement rule from our earlier lesson. It does not create another object.

Calling the superclass method is optional in an override. We choose to do it here because we want the common details as part of the result.

## 9. Avoid two common implementation mistakes

### Accidentally calling the override again

Inside the overriding method, writing `showDetails()` as a way to request the superclass version would call the override again. In this example it would recurse until a `StackOverflowError`.

Use `super.showDetails()` when you intend to invoke the superclass implementation.

### Accidentally declaring an overload

Suppose the superclass declares `showDetails()`, but the subclass declares `showDetails(String label)`.

Those parameter lists differ. The new method is an **overload**, not an override of the no-argument method. Putting `@Override` on that declaration would produce a compiler error in our class hierarchy.

| Declaration in the subclass | Relationship to inherited `showDetails()` |
|---|---|
| `public void showDetails()` | Overrides it |
| `public void showDetails(String label)` | Adds an overload |

An overriding method also cannot reduce the inherited method's accessibility. Since our superclass method is `public`, the override is `public` too. [Official Java overriding rules](https://dev.java/learn/oop/inheritance/).

## 10. Preserve the operation's meaning

In this example, `showDetails()` promises a human-readable display of booking information. Including a scheduled booking's pickup time fits that purpose.

If callers depended on an exact machine-readable output format, adding extra output could break that contract. An override should respect the expectations established by the base type.

Similarly, overriding `cancel()` should not casually bypass the cancellation rules callers rely on. Java's compiler checks language rules, but it cannot verify every business promise.

## 11. Explain it in an interview

> Method overriding occurs when a subclass supplies an implementation of an inherited instance method with a matching signature and compatible return type. For example, `ScheduledBooking` can override `showDetails()` to include its pickup time. `@Override` helps the compiler catch declaration mistakes, and `super.showDetails()` can reuse the superclass implementation. For a normal instance-method call, the implementation is selected according to the actual object's type.
