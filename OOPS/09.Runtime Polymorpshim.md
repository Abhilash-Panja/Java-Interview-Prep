# Java OOP — Runtime Polymorphism (Clarified Walkthrough)

> **One-sentence takeaway:** Polymorphism lets you write code that calls a method on a *general* type, while Java automatically runs the *specific* object's version of that method — no if/else needed.

---

## 1. The Problem in One Picture

You have two kinds of bookings:

```
Booking            →  showDetails() prints ID, passenger, ride type, status
ScheduledBooking   →  showDetails() prints all of that PLUS the pickup time
```

You want **one** piece of code — a printer — that can display *either* kind, without needing to know or check which one it got.

```java
printer.print(regularBooking);     // should print the basic details
printer.print(scheduledBooking);   // should print details + pickup time
```

Same method call. Different results. **That's the whole idea of polymorphism** — everything else in this lesson is just explaining *how* Java pulls that off.

---

## 2. The Printer Doesn't Need to Know the Difference

```java
class BookingPrinter {
    public void print(Booking booking) {
        booking.showDetails();
    }
}
```

Notice what this method **does not** contain:

- ❌ No `if (booking instanceof ScheduledBooking)`
- ❌ No separate `printScheduled()` method
- ❌ No knowledge that `ScheduledBooking` even exists

It just says: *"Whatever you gave me, call `showDetails()` on it."* The parameter type `Booking` is enough — because `ScheduledBooking` **is a** `Booking` (thanks to inheritance).

---

## 3. Two Objects, One Method Call, Two Outcomes

```java
Booking regularBooking = new Booking(101, "Abhilash");
Booking scheduledBooking = new ScheduledBooking(102, "Ravi", "09:00");

BookingPrinter printer = new BookingPrinter();
printer.print(regularBooking);
printer.print(scheduledBooking);
```

| Call | What's actually inside `booking` | Which `showDetails()` runs |
|---|---|---|
| `printer.print(regularBooking)` | a plain `Booking` | `Booking.showDetails()` |
| `printer.print(scheduledBooking)` | a `ScheduledBooking` | `ScheduledBooking.showDetails()` |

**The `print(Booking booking)` method is identical in both calls.** Java looks at the *actual object* sitting inside the variable at runtime, and picks that object's version of the method. This is called **runtime dispatch** — and it's what "runtime polymorphism" means.

---

## 4. The Key Distinction: Declared Type vs. Actual Type

This is the single most important idea in the whole lesson:

```java
Booking booking = new ScheduledBooking(102, "Ravi", "09:00");
```

| | |
|---|---|
| **Declared type** (left side, `Booking`) | Controls **which methods you're allowed to call** — checked at compile time |
| **Actual type** (right side, `ScheduledBooking`) | Controls **which implementation actually runs** — decided at runtime |

Think of it like a **library card**: the card says "General Member," so you can only request what General Members are allowed to request — even if the person holding the card happens to also be a librarian who could technically do more.

```java
booking.showDetails();     // ✅ compiles — Booking promises this method exists
booking.showPickupTime();  // ❌ won't compile — Booking never promised this one,
                            //     even though the actual object has it
```

Compile-time check → *"Is this method on the declared type?"*
Runtime check → *"Which version of it belongs to the real object?"*

Two separate questions, two separate moments.

---

## 5. Tracing the Scheduled Booking Call Exactly

When `printer.print(scheduledBooking)` runs `booking.showDetails()`:

```
1. Java sees the actual object is a ScheduledBooking
2. It runs ScheduledBooking's override of showDetails()
3. That override calls super.showDetails() → prints the common fields
4. Then it calls showPickupTime() → prints the pickup time
```

```java
@Override
public void showDetails() {
    super.showDetails();   // step 3
    showPickupTime();      // step 4
}
```

The printer never sees any of this internal logic — it just triggers the chain by calling one method.

## 6. Full Runnable Example

```java
public class Main {
    public static void main(String[] args) {
        Booking regularBooking = new Booking(101, "Abhilash");
        Booking scheduledBooking =
            new ScheduledBooking(102, "Ravi", "09:00");

        BookingPrinter printer = new BookingPrinter();
        printer.print(regularBooking);
        printer.print(scheduledBooking);
    }
}

class BookingPrinter {
    public void print(Booking booking) {
        booking.showDetails();
    }
}

class Booking {
    private int bookingId;
    private String passengerName;
    private String rideType;
    private String status;

    public Booking(int bookingId, String passengerName) {
        this(bookingId, passengerName, "STANDARD");
    }

    public Booking(int bookingId, String passengerName, String rideType) {
        this.bookingId = bookingId;
        this.passengerName = passengerName;
        this.rideType = rideType;
        this.status = "CONFIRMED";
    }

    public void startRide() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException("Only confirmed bookings can start.");
        }
        status = "STARTED";
    }

    public void cancel() {
        ensureCancellationAllowed();
        status = "CANCELLED";
    }

    private void ensureCancellationAllowed() {
        if (!"CONFIRMED".equals(status)) {
            throw new IllegalStateException("Only confirmed bookings can be cancelled.");
        }
    }

    public String getStatus() {
        return status;
    }

    public void showDetails() {
        System.out.println(bookingId + " | " + passengerName + " | " + rideType + " | " + status);
    }
}

class ScheduledBooking extends Booking {
    private String pickupTime;

    public ScheduledBooking(int bookingId, String passengerName, String pickupTime) {
        super(bookingId, passengerName);
        this.pickupTime = pickupTime;
    }

    public void showPickupTime() {
        System.out.println("Scheduled pickup: " + pickupTime);
    }

    @Override
    public void showDetails() {
        super.showDetails();
        showPickupTime();
    }
}
```

**Output:**

```
101 | Abhilash | STANDARD | CONFIRMED
102 | Ravi | STANDARD | CONFIRMED
Scheduled pickup: 09:00
```

- Line 1 → regular booking, base implementation.
- Lines 2–3 → scheduled booking, override runs, prints common fields **then** the pickup time.

---

## 7. Why This Actually Matters

**Without polymorphism**, the printer would need to grow forever:

```java
// The version you DON'T want to write:
if (booking instanceof ScheduledBooking) {
    // print scheduled details
} else {
    // print regular details
}
```

Every new booking type would mean editing this method again. **With polymorphism**, you can add a `PremiumBooking`, a `GroupBooking`, or anything else that extends `Booking`, and this printer *never changes*. Each new type just brings its own `showDetails()` override, and the printer automatically picks it up.

> This is the real payoff of the whole OOP chain: **inheritance** lets a type reuse and extend another → **overriding** lets it customize behavior → **polymorphism** lets calling code use that customized behavior *without knowing it exists*.

---

## 8. How the Pieces Connect

| Concept | Its job in this example |
|---|---|
| **Inheritance** | Lets `ScheduledBooking` be usable anywhere a `Booking` is expected |
| **Method overriding** | Lets `ScheduledBooking` supply its own `showDetails()` |
| **Runtime polymorphism** | Lets `BookingPrinter` call `showDetails()` once and get the right version automatically |
| **Abstraction** | The printer only needs to know the *contract* (`showDetails()` exists), not the internals |
| **Encapsulation** | Each booking still guards its own state behind its own methods |

---

## 9. One Rule to Tattoo on Your Brain

> **The declared type decides what you can *call*. The actual object decides what *runs*.**

Everything else in this lesson is a consequence of that one sentence.

---

## 10. Test Yourself

```java
Booking booking = new ScheduledBooking(301, "Anita", "14:00");
BookingPrinter printer = new BookingPrinter();
printer.print(booking);
```

1. What's the **declared type** of `booking`?
2. What's the **actual type** of the object it refers to?
3. Which `showDetails()` implementation runs?
4. Why won't `booking.showPickupTime()` compile, even though the real object has that method?

<details>
<summary>Click to reveal the answer</summary>

1. Declared type: `Booking`
2. Actual type: `ScheduledBooking`
3. `ScheduledBooking.showDetails()` runs (which internally calls `super.showDetails()` then `showPickupTime()`)
4. Because compilation only checks the **declared type** (`Booking`), and `Booking` never declared `showPickupTime()`. The compiler doesn't look ahead to see what the actual object *could* do — only what the reference type *promises*.
</details>
