## Question 1: What is the static keyword?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Question 46

**Difficulty**
Beginner

**Interview Frequency**
Very High

**What the Interviewer Is Testing**
Whether you understand class-level vs object-level state.

**Short Interview Answer**
static makes a member belong to the class rather than to an individual object. Static fields are shared by all instances, static methods can be called using the class name, static initializer blocks run as part of class initialization, and nested classes can also be static.

The PDF says static applies to variables, methods, blocks, and nested classes, and that a static field is shared across instances.

### Static Variable

```java
class Employee {

    static String company = "ABC";

    String name;
}
```

Now:

```java
Employee e1 = new Employee();
Employee e2 = new Employee();
```

Conceptually:

```
Employee class
     |
     +---- company = "ABC"

e1
└── name

e2
└── name
```

There is one class-level company value, rather than a separate logical value for every Employee.

### Static Method

```java
class MathUtil {

    static int square(int n) {
        return n * n;
    }
}
```

Usage:

```java
int result = MathUtil.square(10);
```

No object is required.

The PDF also correctly notes that a static method cannot directly use instance members because there is no implicit current object, and consequently this and super are unavailable in ordinary static context.

### Why can't static method directly access instance fields?

```java
class User {

    String name;

    static void print() {
        // System.out.println(name);
    }
}
```

Which object's name?

Object #1?
Object #2?
Object #100?

There is no implicit object.

That's the root reason.

### Static Block

```java
class DatabaseConfig {

    static String url;

    static {
        url = "jdbc:mysql://localhost/test";
    }
}
```

The PDF describes static blocks as class-initialization logic used especially for static fields.

### Common Fresher Mistake

❌ "Static means memory is stored permanently."

Better:
Static is primarily a language ownership/lifetime relationship to the class, not a physical-memory keyword you should explain through rigid JVM-memory claims.

## Question 2: What is final?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Question 13

The PDF says final can prevent reassignment of variables, overriding of methods, and inheritance from classes.

**Short Interview Answer**
final means a language element cannot be changed in a particular way: a final variable cannot be reassigned after assignment, a final method cannot be overridden, and a final class cannot be extended.

### final Variable

```java
final int age = 25;

// age = 30; // compile error
```

### Final Reference

```java
final List<String> names =
        new ArrayList<>();
```

You cannot do:

```java
names = new ArrayList<>();
```

But this is valid:

```java
names.add("Java");
```

This is extremely important.

The PDF says that with an object type "the object cannot be referenced again."

🔄 **Better wording**
The reference variable cannot be reassigned. The referenced object may still be mutable.

So:

```
final reference
      ≠
immutable object
```

### Final Method

```java
class Parent {

    final void process() {
    }
}
```

Cannot be overridden.

The PDF directly confirms final methods cannot be overridden.

### Final Class

```java
final class SecurityToken {
}
```

Invalid:

```java
class Child extends SecurityToken {
}
```

## Question 3: final vs finally vs finalize()

**Priority:** 🔥🔥🔥 Classic Interview Question

### final

Keyword.

final variable
→ cannot be reassigned

final method
→ cannot be overridden

final class
→ cannot be extended

### finally

Exception-handling block.

```java
try {
    ...
} finally {
    ...
}
```

Used for control/cleanup that normally runs as execution leaves the try structure.

The PDF notes exceptional cases such as System.exit() and JVM termination where a finally block cannot execute.

### finalize()

Historical method inherited from Object.

The PDF lists it as a GC-related Object method.

🔄 **Modern interview answer**
finalize() is legacy and should not be used for resource cleanup. Modern Java has deprecated finalization for removal; deterministic resources should use mechanisms such as AutoCloseable and try-with-resources.

So:

```
final
    ≠
finally
    ≠
finalize()
```

## Question 4: What is this?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF uses it in constructor chaining and variable shadowing

**Short Interview Answer**
this refers to the current object. It is commonly used to distinguish instance fields from local variables, call another constructor in the same class using this(...), pass the current object, or return the current object.

### Field Shadowing

```java
class User {

    private String name;

    User(String name) {
        this.name = name;
    }
}
```

Here:

name
→ parameter

this.name
→ current object's field

The PDF's variable-shadowing section explains this exact use of this.

### Can this be used in static context?

No.

Why?

this
→ current object

static method
→ no implicit current object

The PDF explicitly states that this and super cannot be used in static context.

## Question 5: What is super?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Question 48

**Short Interview Answer**
super refers to the immediate superclass context of the current object. It can be used to invoke a superclass constructor, access a hidden parent field, or call an overridden parent implementation.

### Parent Constructor

```java
class Parent {

    Parent(String name) {
        System.out.println(name);
    }
}

class Child extends Parent {

    Child() {
        super("Parent");
    }
}
```

The PDF defines:

this()
→ same-class constructor

super()
→ immediate-superclass constructor

### Parent Method

```java
class Parent {

    void show() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    @Override
    void show() {

        super.show();

        System.out.println("Child");
    }
}
```

Output:

```
Parent
Child
```

## Question 6: this() vs super()

**Priority:** 🔥🔥 Must Know | ⚠️ Version-Sensitive

| this() | super() |
|---|---|
| Calls another constructor in same class | Calls superclass constructor |
| Constructor chaining within class | Initializes superclass portion |
| Cannot create recursive constructor cycle | Refers to direct superclass constructor |

The PDF teaches the traditional rule that this() or super() must be the first statement and therefore cannot both be used in one constructor invocation position.

🔄 **Modern Java note**
That "literally first statement" rule is now version-sensitive. Java 25 delivered Flexible Constructor Bodies, permitting certain safe statements before an explicit this(...) or super(...) constructor invocation. (OpenJDK)

For a fresher interview:
If the interviewer is asking traditional Java rules, explain the classic first-statement rule. If they ask about current Java, mention that newer Java versions relaxed constructor-body syntax while still enforcing initialization-safety restrictions.

That's a much stronger 2026 answer.

## Question 7: What is transient?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Serialization section

**Short Interview Answer**
transient marks an instance field so that Java's default object-serialization mechanism does not persist that field as part of the object's normal serialized state.

Example:

```java
class User implements Serializable {

    String username;

    transient String sessionToken;
}
```

The PDF says static and transient fields do not participate in default serialization and that transient fields receive default values after deserialization.

### After Deserialization

transient int
→ 0

transient boolean
→ false

transient object reference
→ null

unless custom serialization logic restores them.

### Is transient a security keyword?

No.

```java
transient String password;
```

only means:

skip in default Java serialization

It does not automatically:

encrypt
hash
hide from logs
hide from JSON
protect in memory

## Question 8: What is volatile?

**Priority:** 🔥🔥🔥 Must Know
**Source:** 📘 PDF Question 68 + 🔄 modernization

The PDF says volatile applies to variables, not methods or classes, and discusses visibility between threads.

**Short Interview Answer**
volatile is used on shared variables when threads need visibility and ordering guarantees without mutual-exclusion locking. A write to a volatile variable establishes a happens-before relationship with a later read of that same variable. It does not make compound operations such as count++ atomic.

### Example

```java
volatile boolean running = true;
```

Thread 1:

```java
while (running) {
    // work
}
```

Thread 2:

```java
running = false;
```

Volatile ensures the communication has the required Java Memory Model visibility relationship.

🔄 **PDF modernization**
The PDF explains volatile as:

always read/write main memory
instead of thread-local cache

That's a useful beginner analogy, but a more precise interview answer is:

volatile
→ Java Memory Model visibility
→ ordering
→ happens-before

rather than promising literal CPU-cache bypass behavior.

### Does volatile make count++ safe?

No.

```java
volatile int count;
```

Still unsafe:

```java
count++;
```

because conceptually:

```
read
 ↓
increment
 ↓
write
```

Multiple threads can interleave.

## Question 9: What is synchronized?

**Priority:** 🔥🔥🔥 Must Know
**Source:** 📘 PDF Questions 81–84

**Short Interview Answer**
synchronized coordinates access to a critical section using an object's intrinsic monitor. Only a thread owning that same monitor can execute the protected section at a time. Monitor release/acquisition also provides memory-visibility guarantees.

The PDF describes synchronized as protecting shared resources and allowing either an entire method or only a critical block to be synchronized.

### Synchronized Method

```java
synchronized void increment() {
    count++;
}
```

For an instance method, monitor:

this

### Static Synchronized

```java
static synchronized void increment() {
}
```

Monitor:

ClassName.class

The PDF identifies the class-level monitor for static synchronization.

### Reentrancy

The PDF also correctly notes that intrinsic synchronization is reentrant.

If a thread already owns the object's monitor:

```java
synchronized void methodA() {
    methodB();
}

synchronized void methodB() {
}
```

it can enter methodB() without deadlocking against itself.

## Question 10: transient vs volatile

**Priority:** 🔥🔥 Common Confusion

These keywords are completely unrelated.

| transient | volatile |
|---|---|
| Serialization | Concurrency |
| Controls persistence of field | Controls thread visibility/order |
| Used with instance fields | Used with variables |
| Skipped by default Java serialization | Shared reads/writes have JMM semantics |
| No thread-safety guarantee | No serialization behavior |

Mental model:

transient
→ "Should this field be serialized?"

volatile
→ "How should threads observe this field?"

## Question 11: volatile vs synchronized

**Priority:** 🔥🔥🔥 Must Know

| volatile | synchronized |
|---|---|
| Visibility | Visibility |
| Ordering guarantees | Ordering guarantees |
| No mutual exclusion | Mutual exclusion |
| Compound operations not automatically atomic | Can protect compound operations |
| Useful for simple shared state flags | Useful for critical sections/invariants |

Example good for volatile:

```java
volatile boolean shutdown;
```

Example needing coordination:

```java
synchronized void transfer() {

    balance -= amount;
    transactionCount++;
}
```

Multiple related state changes usually need stronger coordination.

## Question 12: What does abstract mean?

**Priority:** 🔥🔥 Must Know
**Source:** 📘 PDF Questions 2–6

The PDF defines an abstract class as one declared with abstract, capable of containing both abstract methods and concrete methods.

**Short Interview Answer**
abstract marks a class as incomplete for direct instantiation or marks a method as requiring implementation by a concrete subclass. An abstract class may contain both implemented and abstract methods.

### Abstract Method

```java
abstract class Payment {

    abstract void process();
}
```

No method body:

```java
abstract void process();
```

Subclass:

```java
class UpiPayment extends Payment {

    @Override
    void process() {
        System.out.println("UPI");
    }
}
```

### Can abstract and final be used together?

**Priority:** ⚠️ Tricky

No for the same class/method intent.

Why?

abstract class
→ subclassing needed to complete behavior

final class
→ subclassing forbidden

Contradiction.

Likewise:

abstract method
→ must be overridden

final method
→ cannot be overridden

So:

```java
abstract final void process();
```

is conceptually contradictory and invalid.

## Question 13: What is instanceof?

**Priority:** 🔥 Important
**Source:** ➕ Dedicated explanation; PDF uses it incidentally in marker-interface discussion

**Short Interview Answer**
instanceof tests whether an object reference is compatible with a particular reference type at runtime.

Example:

```java
Animal animal = new Dog();

System.out.println(
        animal instanceof Dog
);
```

Output:

```
true
```

### Null Behavior

```java
Object obj = null;

System.out.println(
        obj instanceof String
);
```

Output:

```
false
```

It does not throw NullPointerException.

### instanceof vs getClass()

instanceof
→ compatible type?
→ subclasses count

getClass()
→ exact runtime class

Example:

```java
Dog dog = new Dog();
```

```
dog instanceof Animal
→ true
```

while:

```
dog.getClass() == Animal.class
→ false
```

### PDF Precision Note

The PDF uses specific instanceof-based internal explanations for Cloneable and Serializable.

For interviews, don't state those exact internal lines as guaranteed implementation code.

Safer:
Marker-interface protocols can check whether a type/object implements the relevant marker. The exact implementation details of JDK methods are not part of the Java language contract.

## Question 14: Difference between throw and throws

**Priority:** 🔥🔥🔥 Must Know
**Source:** 📘 PDF Question 21

The PDF correctly distinguishes:

throw
→ explicitly throw an exception object

throws
→ declare possible exceptions
in a method signature

### throw

```java
if (age < 18) {
    throw new IllegalArgumentException(
            "Must be 18+"
    );
}
```

### throws

```java
void readFile()
        throws IOException {

    ...
}
```

⚠️ **Important PDF Correction**
The PDF says throw propagates only unchecked exceptions.

That is incorrect.

This is perfectly legal:

```java
void test() throws IOException {

    throw new IOException(
            "Failed"
    );
}
```

So:

throw
→ can throw checked OR unchecked Throwable
subject to normal checked-exception rules

throws
→ declares exception types
that may propagate

## Question 15: break vs continue vs return

**Priority:** 🔥 Important
**Source:** ➕ break/continue; 📘 PDF covers return through exception-output questions

The PDF notes that statements after an unconditional return or throw can become unreachable.

### break

Terminates the nearest applicable loop or switch construct.

```java
for (int i = 0; i < 10; i++) {

    if (i == 5) {
        break;
    }

    System.out.println(i);
}
```

Output:

```
0
1
2
3
4
```

### continue

Skips the remainder of the current loop iteration.

```java
for (int i = 0; i < 5; i++) {

    if (i == 2) {
        continue;
    }

    System.out.println(i);
}
```

Output:

```
0
1
3
4
```

### return

Exits the current method, optionally producing a return value.

```java
int calculate() {
    return 10;
}
```

After an unconditional return:

```java
return 10;

// System.out.println("Hello");
```

the following statement can be unreachable.

### Comparison

break
→ leave loop/switch

continue
→ skip this iteration

return
→ leave entire method

## Question 16: What is native?

**Priority:** ⭐ Important
**Source:** ➕ Added — no dedicated native keyword question was found in the PDF.

**Short Interview Answer**
native declares a method whose implementation is provided outside ordinary Java code, typically through platform/native integration such as JNI. A native method declaration has no Java method body.

Example:

```java
public native void performNativeOperation();
```

Think:

```
Java method declaration
       ↓
native bridge
       ↓
platform implementation
```

### Why was native needed?

Java occasionally needs to interact with:

Operating-system APIs
native libraries
hardware-specific functionality
existing C/C++ code

Historically JNI has been one major mechanism for this.

### Can a native method have a Java body?

No.

You declare:

```java
native void method();
```

not:

```java
native void method() {
    // Java implementation
}
```

### Can native and abstract be combined?

Both describe methods without an ordinary Java implementation body, but for different reasons:

abstract
→ subclass must implement

native
→ implementation exists outside Java

They are conceptually different mechanisms and are not normally combined.

## Question 17: What is strictfp?

**Priority:** ⚠️ Historical / Low Frequency
**Source:** ➕ Not covered in the PDF

Historically, strictfp required consistent strict floating-point evaluation across platforms.

Example syntax:

```java
strictfp class Calculator {
}
```

or historically on methods.

🔄 **Current Java status**
In modern Java, strictfp is obsolete because floating-point expressions use strict semantics by default. The Java SE 25 language specification explicitly says the modifier has no compile-time or runtime effect and should not be used in new code. (Oracle Documentation)

**Interview Answer**
Historically strictfp enforced strict cross-platform floating-point semantics. Since Java 17, Java uses always-strict floating-point semantics, so strictfp is obsolete and has no practical effect in current Java.

🔥 This is a good example of why memorizing an old Java interview book without version awareness can hurt.

## Question 18: What is a constant in Java?

**Priority:** 🔥 Important
**Source:** 📘 PDF Question 52

The PDF recommends:

```java
public static final TYPE NAME = VALUE;
```

and also mentions enum constants.

Example:

```java
public static final int MAX_RETRIES = 3;
```

Why both?

static
→ belongs to class

final
→ cannot be reassigned

So:

static + final
→ one shared non-reassignable constant reference/value

Convention:

UPPER_SNAKE_CASE

### Important Trap: Does static final always mean immutable?

No.

```java
public static final
List<String> NAMES =
        new ArrayList<>();
```

You cannot reassign:

```java
NAMES = new ArrayList<>();
```

But you can still:

```java
NAMES.add("Java");
```

unless the object itself prevents mutation.

Again:

```
final reference
≠
immutable object
```

## Question 19: What is enum?

**Priority:** ⭐ Important
**Source:** 📘 PDF Question 53

The PDF defines an enum as a type containing a fixed set of constants and notes that enums can also contain fields, methods, and constructors.

Example:

```java
enum RideStatus {

    REQUESTED,
    ACCEPTED,
    IN_PROGRESS,
    COMPLETED,
    CANCELLED
}
```

Better than:

```java
String status = "COMPELTED";
```

because enum provides compile-time restriction to valid values.

### Real Spring Boot Example

```java
@Enumerated(EnumType.STRING)
private RideStatus status;
```

Now your domain state is restricted to defined values.

This is much safer than arbitrary Strings.

## Common Fresher Mistakes

❌ **1. "static means global variable."**
Too vague.
Better:
Static member belongs to the class rather than one object.

❌ **2. "final object cannot change."**
Wrong.

```java
final List<String> list =
        new ArrayList<>();

list.add("Java");
```

is valid.

❌ **3. "finally is a keyword used for garbage collection."**
Wrong.
That's unrelated to finalize().

❌ **4. "this refers to the class."**
No.
this
→ current object

❌ **5. "super refers to every parent class."**
More precisely:
It provides access to the immediate superclass context.

❌ **6. "transient means temporary variable."**
No.
It specifically affects default Java serialization.

❌ **7. "volatile makes operations atomic."**
No.

```java
volatile int count;

count++;
```

is still unsafe as a concurrent compound operation.

❌ **8. "synchronized locks the method."**
Better:
A monitor associated with an object or Class is acquired.

❌ **9. "abstract class must contain abstract methods."**
No.
An abstract class can contain zero abstract methods.

❌ **10. "instanceof null throws NPE."**
No.
It evaluates to false.

❌ **11. "throw works only with unchecked exceptions."**
Wrong.
The PDF itself is misleading here; checked exceptions can also be explicitly thrown.

❌ **12. "strictfp is important for current Java floating-point consistency."**
Historical knowledge only. It is obsolete in current Java.

## Interviewer Grill Round — Java Keywords

**Interviewer**
What does static mean?

**Candidate**
It means the member belongs to the class rather than to one instance. Static fields are shared class-level state and static methods have no implicit current object.

---

**Interviewer**
Why can't a static method directly use this?

**Candidate**
Because this means the current instance, while a static method can execute without any particular instance.

---

**Interviewer**
What does final mean?

**Candidate**
For a variable it prevents reassignment, for a method it prevents overriding, and for a class it prevents inheritance.

---

**Interviewer**
```java
final List<String> list =
        new ArrayList<>();

list.add("Java");
```
Compile?

**Candidate**
Yes. Final prevents the reference variable from being reassigned; it doesn't make the ArrayList immutable.

---

**Interviewer**
final, finally, finalize()?

**Candidate**
Final is a language modifier, finally belongs to exception handling, and finalize is a legacy object-finalization method that should not be used in modern code.

---

**Interviewer**
What is this?

**Candidate**
A reference to the current object.

---

**Interviewer**
What is super?

**Candidate**
A way to access the immediate superclass constructor, overridden methods, or hidden superclass members.

---

**Interviewer**
Difference between this() and super()?

**Candidate**
this() invokes another constructor in the same class; super() invokes a constructor of the immediate superclass.

---

**Interviewer**
Must they literally be the first line?

**Candidate**
That's the traditional Java rule taught in older material. Modern Java 25 Flexible Constructor Bodies allows restricted safe statements before an explicit constructor invocation, so the exact answer is version-sensitive.

🔥 Excellent modern answer.

---

**Interviewer**
What does transient do?

**Candidate**
It excludes an instance field from Java's default object-serialization state.

---

**Interviewer**
Does transient encrypt a password?

**Candidate**
No. It only affects default Java native serialization.

---

**Interviewer**
What is volatile?

**Candidate**
It provides Java Memory Model visibility and ordering guarantees for a shared variable but does not provide mutual exclusion or make compound operations atomic.

---

**Interviewer**
Then is this thread-safe?
```java
volatile int count;

count++;
```

**Candidate**
No, because increment is a read-modify-write compound operation.

---

**Interviewer**
Then what would you use?

**Candidate**
Depending on the requirement, AtomicInteger.incrementAndGet() or synchronization/locking.

---

**Interviewer**
Difference between synchronized and volatile?

**Candidate**
Both can provide visibility guarantees, but synchronized additionally provides mutual exclusion around a critical section. Volatile doesn't make compound state changes atomic.

---

**Interviewer**
Can an abstract class be final?

**Candidate**
No. Abstract means subclassing is needed to complete behavior, while final forbids subclassing.

---

**Interviewer**
Can an abstract method be final?

**Candidate**
No. An abstract method must be implemented through overriding, whereas a final method cannot be overridden.

---

**Interviewer**
What does instanceof do?

**Candidate**
It checks whether a reference's runtime object is compatible with a specified reference type.

---

**Interviewer**
What happens here?
```java
Object x = null;

System.out.println(
        x instanceof String
);
```

**Candidate**
It prints false.

---

**Interviewer**
throw vs throws?

**Candidate**
throw actually throws a Throwable object from code. throws declares in a method signature which exceptions may propagate.

---

**Interviewer**
Can throw throw IOException?

**Candidate**
Yes. Checked exceptions can be explicitly thrown; they simply have to obey catch-or-declare rules.

---

**Interviewer**
Break vs continue?

**Candidate**
Break exits the loop, while continue skips the remainder of the current iteration and moves to the next iteration.

---

**Interviewer**
Break vs return?

**Candidate**
Break exits only the applicable loop or switch; return exits the entire current method.

---

**Interviewer**
What is native?

**Candidate**
It declares a method whose implementation comes from outside ordinary Java code, traditionally through native integration such as JNI.

---

**Interviewer**
What is strictfp?

**Candidate**
Historically it enforced strict floating-point semantics. Modern Java uses always-strict floating-point behavior, so strictfp is obsolete.
